## 1. 目的与原则

测试文件库用于往返测试、编辑测试、渲染比对、OCR 评测、条码和标签测试、性能基准（方案 13.2）。

原则：
1. **能自制就不用真实文件**；用真实文件必须先脱敏。
2. **真实文件只在本机和受控存储里处理**，不上传任何外部服务，包括在线 OCR、在线 PDF 工具、翻译和大模型服务。
3. **每个文件可追溯**：来源、授权、脱敏人、复核人都有记录（第 6 节）。
4. **按来源分类统计**，避免总平均数掩盖某一类文件的问题（方案 13.1）。

## 2.1 公开测试集的组织

公开测试集（G 类）按 `public/<仓库名>/<子目录>` 保存，如 `public/pdfium/resources`、`public/pdfium/pixel`、`public/pdfjs/`，保留原文件名，便于对照上游。P0 结束时的情况：PDFium 的那一批（346 个文件）有取文件的脚本（`scripts/fetch-public-corpus.ps1`），进了每晚的往返测试；pdf.js 的测试文件（`test/pdfs`，1092 个）只在 V17 合入时手工取、手工跑过一次，还没有接进脚本和每晚的测试。往返测试按相对路径的第一级目录（`pdfium`、`pdfjs`）区分"来源"；PDFium 内部的 `resources`、`pixel`、`javascript`、`xfa` 四个子目录性质差别明显（回归用例、像素测试、脚本、XFA），报告里按子目录单独列一行。入库清单的规则见 `tests/corpus/public/README.md`。

## 3. 收集渠道

### 3.1 自制

- 用不同软件和版本生成：Microsoft Office（2016、2019、2021、365）、WPS、Adobe 设计软件、CorelDRAW、Chrome 和 Edge 的打印。
- 扫描件：自制文档打印后，按不同分辨率、黑白和彩色扫描；手机在不同光线、角度下拍照。
- 货代单证：用虚构的公司、地址和编号。编号要符合校验规则（《货代业务规则》第 1 节），否则会干扰校验类测试。
- 印章：用写明"样本"字样的虚构印章，不仿制任何真实单位的印章。

### 3.2 公开来源

- PDF.js、PDFium 仓库的测试文件，按各自许可使用，manifest 里记录许可。
- 其他公开网站上的 PDF 只作内部测试，记录网址和下载日期，不对外分发。

### 3.3 用户访谈和合作货代

- 对方签署样本使用同意书：用途只限内部测试；脱敏后才入库；原件的保存期限；对方可随时要求删除。我方签署保密协议。
- 对方先自行删掉不愿提供的内容。
- 用加密 U 盘或企业网盘的受限目录交接原件，不用微信、邮件附件传递。

## 4. 脱敏

### 4.1 必须处理的信息

| 信息 | 处理方式 |
|---|---|
| 人名、电话、邮箱、证件号码 | 替换为虚构值，格式不变 |
| 公司名称、地址 | 替换为 SAMPLE 开头的虚构名称和虚构地址，长度、行数与原来相近 |
| 银行账号、税号 | 替换为虚构值 |
| 提单号、箱号、封号、空运单号、订单号 | 替换为虚构值，校验位保持正确 |
| 金额、数量 | 可以保留；对方要求时按比例调整 |
| 印章、签名 | 换成虚构的样本印章和签名 |
| 条码、二维码 | 按替换后的数据重新生成，码制和尺寸不变 |
| 文档元数据 | 清除 Info 字典和 XMP 里的作者、公司、创建工具中的公司信息 |
| 附件、JavaScript、嵌入文件 | 删除 |

### 4.2 方法

- **原生 PDF**：用真正删除内容的工具删除原文字，再写入替换文字，例如 Acrobat Pro 的"涂黑"功能，或经过验证的脚本。不能只盖白框，否则原文字还在文件里。P1 起可以用 MagPDF 自己做，顺便测试编辑功能，但都要经过 4.3 的检查。
- **扫描件**：在图像上用背景色涂掉原内容，再叠加替换内容；或者打印替换后的版本重新扫描。
- **脱敏会破坏测试价值的**（例如签名验证测试必须保留原签名）：不进普通文件库，放受限库（4.4）。

### 4.3 检查

- **自动检查**：提取全部文字（包括不可见文字层）和元数据，用规则查找手机号、邮箱、18 位身份证号（含校验位）、银行卡号（Luhn 校验）、常见公司名后缀（"有限公司"、"Co., Ltd."等），命中项逐条人工确认。
- **人工复核**：由脱敏人以外的第二个人逐页查看，扫描件放大到 200% 检查残留笔画。
- 脱敏人、复核人和日期记在 manifest 里。

### 4.4 原件与受限库

- 原件只放在加密存储里（BitLocker 加密的专用硬盘，或企业网盘的受限目录），只有测试组和样本对接人能访问。
- 脱敏复核完成后 30 天内删除原件，在 manifest 里记录删除日期；同意书另有约定的按约定。
- 受限库存放不能脱敏又必须保留的样本：单独存放、单独授权、记录访问日志、到期删除，不进 CI。

## 5. 存储与访问

- 测试文件库放在独立仓库（Git LFS 或企业网盘），不进主代码仓库。主仓库的 `tests/corpus/` 只放 manifest、同步脚本和少量自制小样本；当前已入库 `synthetic/`（60 份，约 109 KB）、`synthetic-text/`（V08 的文字样本，超过 1 MB 的不入库）和 `public/` 的说明与入库清单。`synthetic-ocr/`（V09 的合成扫描图）和 `perf/`（性能测量用的页面）只入库生成脚本，生成的文件不入库。
- CI 只读访问；开发者按需同步需要的分类。
- 禁止把任何样本上传到外部服务：在线 OCR、在线 PDF 工具、翻译、大模型、公共网盘。
- 成员离职或调岗时当天回收访问权限。

## 6. 清单（manifest）

每个来源目录放一份 `manifest.json`，同一目录的文件共用一个清单；`synthetic/` 由 `generate.py` 自行生成。用 `tests/corpus/tools/make_manifest.py <目录>` 生成或更新（调用 `magpdf-cli info --json` 取页数与对象统计），再次运行时保留人工填写的字段。CI 汇总各目录的清单出报告。

| 字段 | 说明 |
|---|---|
| `id` | 分类字母加序号，如 `F-0123` |
| `category` | A–H、S |
| `file` | 相对目录的文件名 |
| `sha256` | 文件校验值，用于去重和完整性检查 |
| `size` | 文件字节数，和 `sha256` 一起做完整性检查 |
| `title` | 一句话标题 |
| `pages` | 页数 |
| `group` | 缺陷 / 场景分组（`color`、`shading`、`extgstate`、`text`、`structure`、`composite` 等），报告按它分组统计 |
| `refs` | 涉及的方案或计划条目，如 `方案 2.1 Type3`、`P0 计划 V03 第 4 项` |
| `origin` | `self` 自制、`public` 公开、`partner` 合作方、`interview` 访谈收集 |
| `license` | 公开样本填许可证；合作方样本填同意书编号 |
| `desensitized` | `yes` / `no` / `na`（自制样本不需要） |
| `desensitizedBy`、`reviewedBy`、`reviewedOn` | 脱敏人、复核人、复核日期 |
| `originalDeletedOn` | 原件删除日期 |
| `tags` | 特征标签，如 `cmyk`、`spot`、`smask`、`overprint`、`type3`、`tagged`、`signed`、`encrypted`、`scan-300dpi`、`phone-photo`、`lang-zh`、`lang-en`、`barcode`、`multi-up-labels`、`text-labels` |
| `expect` | 机器可比对的预期：`pages` 与每页 `width/height/rotation/objects/text/path/image/shading/form`，供校验工具和 CI 使用 |
| `check`、`checkNote` | `pass`（结构检查必须干净）或 `expect-warn`（故意损坏，必须报警），用来区分预期失败 |
| `pdfVersion` | 文件头版本 |
| `generator` | 自制样本的生成脚本路径，表明可重新生成 |
| `note` | 自由备注（如"由 .in 模板生成"、"magpdf-cli 打不开"） |
| `expected` | **要观察的现象 / 已知问题**（人读），如"已知不能保真：原因"；与机器比对的 `expect` 区分，不混用 |
| `issues` | 关联的缺陷编号 |

`tags` 让测试报告既能按来源统计，也能按特征统计，例如"带软蒙版的页面无差异比例"。

## 7. 标注规范

### 7.1 OCR 标注

- **工具**：PPOCRLabel（PaddleOCR 的标注工具，Apache-2.0），在本机运行。
- **标注单位**：文字行。每行标一个贴合文字外沿的四边形，加上转写文字。
- **转写规则**：
  - 照原样转写，不纠正原文的错别字；全角、半角照原样。
  - 印章里的文字不标，另标印章区域，类别 `seal`。
  - 手写文字只标区域，打标签 `handwriting`，不计入准确率，用来统计误识别（方案 6.6：手写不在 v1 范围）。
  - 看不清的单字用 `□` 代替，该字不计入统计。
- **复标抽查**：每批随机抽 10% 由第二个人重标，字符一致率低于 99% 的批次返工。
- **格式**：PaddleOCR 标注格式，每行是"图像路径 + 制表符 + JSON 数组"，数组元素为 `{"transcription": "…", "points": [[x, y], …]}`。
- **指标定义**：
  - 字符准确率 = 1 − 各行编辑距离之和 ÷ 标注字符总数，按页面语言分别统计。
  - 文字行召回率 = 与标注行交并比 ≥ 0.5 的检测行数 ÷ 标注行数。
- **P0 实测时碰到的口径问题**（V09 报告 9.3）。通过线对着哪个数还没有定；定下来之前，评测时两个数都报：
  - 一条标注行被检测切成几段：现在的算法是一条标注行只配一个检测框，切成两段就整行算错，这个数反映“一行是不是一个编辑单位”。另报把各段按位置接起来再比的数，它反映“搜不搜得到、复制出来对不对”。合成的英文页上前一个数是 97.15%，后一个是 99.39%。
  - 中英文之间的空格、全角和半角：标注照原样转写不变；统计时另报一个“不计空格、全角半角归一”的数。合成的中英对照页上是 93.79% 和 99.09%。
  - 一行里既有中文又有英文的页单列一类，不并进中文页或英文页。

### 7.2 文字层行 / 段标注

原生 PDF 的行 / 段落聚类评测（V07）用《V07-标注格式》，要点：

- **格式**：JSON，UTF-8，`<样本名>.labels.json`，与样本同名放在样本旁边；格式标识 `magpdf-text-labels/1`，字段和评测指标见该文档。
- **标注单位**：PDFium 文字页的字符索引（闭区间），按页分行和段落。评测与渲染分辨率无关。
- **入库**：`manifest.json` 的 `tags` 加 `text-labels`；`--emit-labels --with-text` 生成的预标注会把文字片段写进 `note`，含敏感信息的备注入库前必须删除。
- **复标抽查**：每批随机抽 10% 由第二人独立标注，把两份标注互相比对，行字符一致率低于 99%、段低于 95% 的批次返工。
- **指标**：字符一致率（主）与完全匹配率（辅），按来源和特征分组汇总。

本格式面向 PDF 文字层，不含转写；扫描件 OCR 文字层的评测仍用 7.1，两者不能互换。

## 8. 维护

- 每修复一个缺陷，把能复现问题的样本（脱敏后）加入文件库，manifest 的 `issues` 填缺陷编号。
- 每季度清点一次：按 `sha256` 去重，补充薄弱分类，复核受限库到期删除。
- 文件库总量控制在 CI 一晚能跑完全量的范围内，初定 20 GB。超出时改为每晚跑子集、每周跑全量。
