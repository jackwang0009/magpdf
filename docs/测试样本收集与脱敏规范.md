## 1. 目的与原则

测试文件库用于往返测试、编辑测试、渲染比对、OCR 评测、条码和标签测试、性能基准（方案 13.2）。

原则：
1. **能自制就不用真实文件**；用真实文件必须先脱敏。
2. **真实文件只在本机和受控存储里处理**，不上传任何外部服务，包括在线 OCR、在线 PDF 工具、翻译和大模型服务。
3. **每个文件可追溯**：来源、授权、脱敏人、复核人都有记录（第 6 节）。
4. **按来源分类统计**，避免总平均数掩盖某一类文件的问题（方案 13.1）。

## 3. 收集渠道

### 3.1 自制

- 用不同软件和版本生成：Microsoft Office（2016、2019、2021、365）、WPS、Adobe 设计软件、CorelDRAW、Chrome 和 Edge 的打印。
- 扫描件：自制文档打印后，按不同分辨率、黑白和彩色扫描；手机在不同光线、角度下拍照。
- 货代单证：用虚构的公司、地址和编号。编号要符合校验规则（《货代业务规则》第 1 节），否则会干扰校验类测试。
- 印章：用写明"样本"字样的虚构印章，不仿制任何真实单位的印章。

### 3.2 公开来源

- PDF.js、PDFium 仓库的测试文件，按各自许可使用，manifest 里记录许可。
- 其他公开网站上的 PDF 只作内部测试，记录网址和下载日期，不对外分发。

### 3.3 用户访谈和合作货代

- 对方签署样本使用同意书：用途只限内部测试；脱敏后才入库；原件的保存期限；对方可随时要求删除。我方签署保密协议。
- 对方先自行删掉不愿提供的内容。
- 用加密 U 盘或企业网盘的受限目录交接原件，不用微信、邮件附件传递。

## 4. 脱敏

### 4.1 必须处理的信息

| 信息 | 处理方式 |
|---|---|
| 人名、电话、邮箱、证件号码 | 替换为虚构值，格式不变 |
| 公司名称、地址 | 替换为 SAMPLE 开头的虚构名称和虚构地址，长度、行数与原来相近 |
| 银行账号、税号 | 替换为虚构值 |
| 提单号、箱号、封号、空运单号、订单号 | 替换为虚构值，校验位保持正确 |
| 金额、数量 | 可以保留；对方要求时按比例调整 |
| 印章、签名 | 换成虚构的样本印章和签名 |
| 条码、二维码 | 按替换后的数据重新生成，码制和尺寸不变 |
| 文档元数据 | 清除 Info 字典和 XMP 里的作者、公司、创建工具中的公司信息 |
| 附件、JavaScript、嵌入文件 | 删除 |

### 4.2 方法

- **原生 PDF**：用真正删除内容的工具删除原文字，再写入替换文字，例如 Acrobat Pro 的"涂黑"功能或经过验证的脚本。不能只盖白框，否则原文字还在文件里。P1 起可以用 MagPDF 自己做，顺便测试编辑功能，但都要经过 4.3 的检查。
- **扫描件**：在图像上用背景色涂掉原内容，再叠加替换内容；或者打印替换后的版本重新扫描。
- **脱敏会破坏测试价值的**（例如签名验证测试必须保留原签名）：不进普通文件库，放受限库（4.4）。

### 4.3 检查

- **自动检查**：提取全部文字（包括不可见文字层）和元数据，用规则查找手机号、邮箱、18 位身份证号（含校验位）、银行卡号（Luhn 校验）、常见公司名后缀（"有限公司"、"Co., Ltd."等），命中项逐条人工确认。
- **人工复核**：由脱敏人以外的第二个人逐页查看，扫描件放大到 200% 检查残留笔画。
- 脱敏人、复核人和日期记在 manifest 里。

### 4.4 原件与受限库

- 原件只放在加密存储里（BitLocker 加密的专用硬盘，或企业网盘的受限目录），只有测试组和样本对接人能访问。
- 脱敏复核完成后 30 天内删除原件，在 manifest 里记录删除日期；同意书另有约定的按约定。
- 受限库存放不能脱敏又必须保留的样本：单独存放、单独授权、记录访问日志、到期删除，不进 CI。

## 5. 存储与访问

- 测试文件库放在独立仓库（Git LFS 或企业网盘），不进主代码仓库。主仓库的 `tests/corpus/` 只放 manifest、同步脚本和少量自制小样本。
- CI 只读访问；开发者按需同步需要的分类。
- 禁止把任何样本上传到外部服务：在线 OCR、在线 PDF 工具、翻译、大模型、公共网盘。
- 成员离职或调岗时当天回收访问权限。

## 6. 清单（manifest）

每个样本在 `tests/corpus/manifest.csv` 里占一行：

| 字段 | 说明 |
|---|---|
| `id` | 分类字母加序号，如 `F-0123` |
| `category` | A–H |
| `file` | 文件库内的相对路径 |
| `sha256` | 文件校验值，用于去重和完整性检查 |
| `pages` | 页数 |
| `origin` | `self` 自制、`public` 公开、`partner` 合作方、`interview` 访谈收集 |
| `license` | 公开样本填许可证；合作方样本填同意书编号 |
| `desensitized` | `yes` / `no` / `na`（自制样本不需要） |
| `desensitizedBy`、`reviewedBy`、`reviewedOn` | 脱敏人、复核人、复核日期 |
| `originalDeletedOn` | 原件删除日期 |
| `tags` | 特征标签，如 `cmyk`、`spot`、`smask`、`overprint`、`type3`、`tagged`、`signed`、`encrypted`、`scan-300dpi`、`phone-photo`、`lang-zh`、`lang-en`、`barcode`、`multi-up-labels` |
| `expected` | 已知问题或预期结果，如"已知不能保真：原因" |
| `issues` | 关联的缺陷编号 |

`tags` 让测试报告既能按来源统计，也能按特征统计，例如"带软蒙版的页面无差异比例"。

## 7. OCR 标注规范

- **工具**：PPOCRLabel（PaddleOCR 的标注工具，Apache-2.0），在本机运行。
- **标注单位**：文字行。每行标一个贴合文字外沿的四边形，加上转写文字。
- **转写规则**：
  - 照原样转写，不纠正原文的错别字；全角、半角照原样。
  - 印章里的文字不标，另标印章区域，类别 `seal`。
  - 手写文字只标区域，打标签 `handwriting`，不计入准确率，用来统计误识别（方案 6.6：手写不在 v1 范围）。
  - 看不清的单字用 `□` 代替，该字不计入统计。
- **复标抽查**：每批随机抽 10% 由第二个人重标，字符一致率低于 99% 的批次返工。
- **格式**：PaddleOCR 标注格式，每行是"图像路径 + 制表符 + JSON 数组"，数组元素为 `{"transcription": "…", "points": [[x, y], …]}`。
- **指标定义**：
  - 字符准确率 = 1 − 各行编辑距离之和 ÷ 标注字符总数，按页面语言分别统计。
  - 文字行召回率 = 与标注行交并比 ≥ 0.5 的检测行数 ÷ 标注行数。

## 8. 维护

- 每修复一个缺陷，把能复现问题的样本（脱敏后）加入文件库，manifest 的 `issues` 填缺陷编号。
- 每季度清点一次：按 `sha256` 去重，补充薄弱分类，复核受限库到期删除。
- 文件库总量控制在 CI 一晚能跑完全量的范围内，初定 20 GB。超出时改为每晚跑子集、每周跑全量。
