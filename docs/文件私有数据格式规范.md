# MagPDF 文件私有数据格式规范

| 项 | 内容 |
|---|---|
| 版本 | v0.1 |
| 状态 | 草案，P1 开工前定稿 |
| 日期 | 2026-11-06 |
| 负责组 | 引擎组 |
| 依据 | 《MagPDF 技术方案》v0.6：4.1、6.2、9.3、10.2、10.6、11.4、11.8 |

用户保存的文件要多年后仍能正确打开，所以本规范在 P1 开始写文件之前定稿，此后 v1 只增不改。

---

## 1. 范围与原则

范围：MagPDF 写进 PDF 的私有数据，以及保存在本机的数据文件（模板库、组件库、印章库、恢复文件、OCR 缓存、偏好设置）。

原则：
1. **写出的仍是标准 PDF**：其他阅读器忽略私有数据后，显示和打印结果与 MagPDF 一致。套打底图"打印时隐藏"也用标准的可选内容机制实现（第 6 节）。
2. **只用规范允许扩展的位置**：标记内容的属性字典、文档目录里的私有键、可选内容组。
3. **只增不改**：已发布的键不改含义、不改类型；旧版本软件遇到新键时忽略并原样保留。
4. **能用 PDFium 现有接口写出**：标记内容参数只用整数、字符串、字节串三种类型，对应 `FPDFPageObjMark_SetIntParam`、`FPDFPageObjMark_SetStringParam`、`FPDFPageObjMark_SetBlobParam`。需要扩展接口的地方单独注明。

## 2. 总览

| 数据 | 存放位置 | 写入阶段 |
|---|---|---|
| 文档级信息、模板信息 | 文档目录中的 `/MagPDF` 字典（第 3 节） | P1 |
| 对象名称、锁定 | 包住对象的标记内容 `/MagPDF`（第 4 节） | P1 |
| 组件类型与参数 | 同上，带 `/Comp` 键（4.3） | P1 |
| OCR 文字层 | 同上，带 `/Role (OCRText)`（4.4） | P1 |
| 编组 | 标记内容 `/MagGroup`（第 5 节） | P1 |
| 不打印图层（套打底图） | 可选内容组 OCG（第 6 节） | P3 |
| 扫描件改字的文字和补丁 | 标记内容 `/MagPDF`，带 `/Role`（4.4） | v1.1，键现在预留 |

## 3. 文档级字典

在文档目录（Catalog）中加私有键 `/MagPDF`：

```
/MagPDF <<
  /Fmt 1                          % 私有数据格式版本
  /Gen (MagPDF 1.0.0)             % 最后一次写入的软件版本
  /Template <<                    % 只有模板文件才有
    /Name <FEFF63D053555957 6253>  % 模板名称，文本串
    /Cat <FEFF59576253>           % 分类
    /Kind (overlay)               % normal 普通模板；overlay 套打模板
    /Rev 3                        % 模板修订号，每次"编辑模板"并保存后加 1
    /Created (D:20261106190000+08'00')
    /Modified (D:20261106193000+08'00')
  >>
  /FromTpl << /Name <FEFF...> /Rev 3 >>   % 可选：从哪个模板新建
>>
```

- `/Gen` 每次保存时更新。
- "存储为模板"时写入 `/Template`（方案 10.3）。从模板新建的副本删除 `/Template`，改写 `/FromTpl`，便于以后知道单据出自哪个模板。
- `/Fmt` 高于软件支持的版本时：文档照常打开和编辑，但私有数据只读，组件按普通编组处理；保存时原样保留没有改动的私有数据。

## 4. 对象级标记内容 `/MagPDF`

### 4.1 写法

```
/MagPDF << /Name <FEFF6536 8D27 4EBA> /Lock 1 >> BDC
  q ... Q
EMC
```

- **放在最内层**：对象已有带标签 PDF 的 `/P << /MCID n >> BDC`，或可选内容的 `/OC /MC0 BDC` 时，`/MagPDF` 写在它们里面，不打乱原有结构。
- **不跨内容流**：一个标记内容序列必须完整位于一个内容流内（PDF 规范要求）。跨流调整层级时，生成器先合并相关内容流（方案 2.3 第 5 条）。
- **内联字典**：属性字典直接写在内容流里，不放进资源字典的 `/Properties`。
- **没有键就不加标记**：对象既没有名称也没有锁定、也不是组件时，不加 `/MagPDF`。

### 4.2 键

| 键 | 类型 | 含义 | 何时写 |
|---|---|---|---|
| `/Name` | 字节串：纯 ASCII，或 UTF-16BE 加 BOM `FE FF` | 图层面板中的名称 | 用户改过名称 |
| `/Lock` | 整数 1 | 锁定 | 锁定时写 1，解锁时删除该键 |
| `/Comp` | ASCII 字符串 | 组件类型，取值见《组件参数定义》 | 组件 |
| `/Ver` | 整数 | 组件参数的结构版本 | 组件 |
| `/Params` | 字节串，UTF-8 JSON | 组件参数 | 组件 |
| `/M` | 字符串，6 个数 | 组件放置矩阵，只含旋转和平移，单位 pt | 组件 |
| `/Hash` | 字符串，32 位小写十六进制 | 生成结果校验值（4.5） | 组件 |
| `/Tab` | 整数，从 1 起 | 套打填写顺序（方案 10.6） | 套打模板里的字段 |
| `/GID` | ASCII 字符串 | 跨页组件的组标识，如骑缝章各页分片共用一个 | 跨页组件 |
| `/Part` | 字符串 `i/n` | 本片是第几片、共几片 | 跨页组件 |
| `/Role` | ASCII 字符串 | 特殊用途（4.4） | OCR 文字层等 |

字节串写出时一律用十六进制字符串 `<...>`，避免转义问题。

### 4.3 组件

一个组件是一个 `/MagPDF` 标记内容序列，加上序列里的若干普通对象。例如条码组件是一个填充路径（全部条）加一个文字对象（可读文字）：

```
/MagPDF << /Comp (barcode1d) /Ver 1 /M (1 0 0 1 340.157 680.315)
           /Params <7B2273796D626F6C6F6779223A...> /Hash (9f2c41d07a5be3e6c0d1a2b3c4d5e6f7) >> BDC
  q 0 g ... f Q
  q BT /F3 8 Tf ... Tj ET Q
EMC
```

- **参数**：`/Params` 的 JSON 结构由《组件参数定义》规定，键名用小驼峰（如 `moduleWidth`）。
- **放置矩阵**：`/M` 是组件局部坐标到页面坐标的变换，只含旋转和平移；缩放已经折算进参数（方案 11.3：缩放条码改的是模块宽度和条高）。移动、旋转组件只改 `/M` 和对象位置，不改 `/Params`、`/Hash`。
- **不嵌套**：组件里不再包含组件；编组可以包含组件。
- **解散组件**：删除 `/Comp /Ver /M /Params /Hash /Tab /GID /Part`，对象转成一个普通编组（第 5 节），名称和锁定状态随之转过去。
- **实现注意**：PDFium 的生成器按"标记项是否为同一个"决定相邻对象是否共用一个 `BDC … EMC`。`FPDFPageObj_AddMark` 每次都新建标记项，所以组件里的多个对象要共用一个标记项，需要扩展接口 `MAG_PageObjs_AddSharedMark`（见《接口协议》第 9 节）。序列里的对象在 z 序上必须连续。

### 4.4 `/Role` 取值

| 值 | 含义 | 额外的键 | 阶段 |
|---|---|---|---|
| `OCRText` | MagPDF 写入的不可见 OCR 文字层（`Tr 3`），每页一个序列 | `/Engine`（如 `PP-OCRv5_mobile`）、`/Lang`（如 `ch`、`en`） | P1 |
| `ScanText` | 扫描件改字后放入的可编辑文字（方案 6.3） | `/GID` | v1.1 |
| `ScanPatch` | 盖住原文字的补丁图像（方案 6.4） | `/GID`，与对应的 `ScanText` 相同 | v1.1 |

重新识别时，只替换 `/Role (OCRText)` 的文字层。其他软件生成的不可见文字层，按方案 6.1 由用户选择保留还是替换。

### 4.5 校验值算法

打开文档时重算组件的校验值，与 `/Hash` 不一致，说明组件里的对象被其他软件改过（方案 8.6、11.4）。算法要保证：外观不变时，重新保存、重新子集化、换压缩方式都不改变校验值。

1. 用 `/M` 的逆矩阵把序列里的对象变换到组件局部坐标系。
2. 按 z 序把每个对象写成一行规范文本：
   - 行首是类型字母：`P` 路径，`T` 文字，`I` 图像。
   - 数值保留 3 位小数，去掉末尾的 0，`-0` 写成 `0`。
   - 路径：填充规则（`nz` 或 `eo`，不填充写 `-`）、描边线宽（不描边写 `-`）、填充色和描边色（色彩空间名加分量），然后依次写路径段 `m x y`、`l x y`、`c x1 y1 x2 y2 x3 y3`、`h`。
   - 文字：字体族名（去掉子集前缀 `ABCDEF+`）、字号、文字矩阵、颜色、Unicode 文本（经 ToUnicode 映射）。用 Unicode 而不用字符码，是因为重新子集化可能改变字符码。
   - 图像：宽、高、色彩空间、解码后像素数据的 SHA-256。
3. 各行用 `\n` 连接，按 UTF-8 编码后算 SHA-256，取前 16 字节，写成 32 位小写十六进制。

## 5. 编组 `/MagGroup`

```
/MagGroup << /Name <FEFF...> /Lock 1 >> BDC
  ...若干对象或组件...
EMC
```

- 键与 4.2 的 `/Name`、`/Lock` 相同。没有键时写空字典 `<< >>`；读取时 `/MagGroup BMC` 也认。
- 编组可以嵌套。
- 编组内的对象必须在同一个内容流里、z 序连续；跨流编组时生成器先合并内容流。

## 6. 不打印图层（套打底图，P3）

### 6.1 可选内容组

```
12 0 obj
<< /Type /OCG
   /Name <FEFF5957 6253 5E95 56FE>
   /Usage << /View << /ViewState /ON >> /Print << /PrintState /OFF >> >>
   /MagPDF << /Role (OverlayBackground) >>
>>
endobj
```

`/Name` 是"套打底图"的 UTF-16BE。`/MagPDF /Role` 让 MagPDF 认出这是套打底图层，其他阅读器会忽略。

### 6.2 文档目录

```
/OCProperties <<
  /OCGs [12 0 R]
  /D << /Order [12 0 R]
        /ON [12 0 R]
        /AS [ << /Event /Print /OCGs [12 0 R] /Category [/Print] >>
              << /Event /View  /OCGs [12 0 R] /Category [/View]  >> ]
        /Locked [12 0 R] >>
>>
```

- 文件里已有 `/OCProperties` 时，追加到原有数组，不覆盖原有图层和配置。
- `/AS` 让阅读器在打印时按 `/Usage` 隐藏该层。PDFium 用 `FPDF_PRINTING` 渲染时同样遵守，所以 MagPDF 的打印和打印前条码检查都按打印用途渲染。
- `/Locked` 让 Acrobat 等阅读器的图层面板不能切换这一层，避免误操作。

### 6.3 内容流

```
/OC /MC0 BDC                       % 页面资源 /Properties << /MC0 12 0 R >>
  /MagPDF << /Lock 1 >> BDC
    q 595.276 0 0 841.89 0 0 cm /Im1 Do Q
  EMC
EMC
```

底图对象同时锁定，锁定标记写在 `/OC` 里面（4.1 的"最内层"规则）。

## 7. 编码约定

| 内容 | 编码 |
|---|---|
| 名称、分类等给人看的文字 | 纯 ASCII 直接写；含其他字符时用 UTF-16BE，带 BOM `FE FF` |
| `/Params` | UTF-8 JSON，十六进制字符串写出 |
| `/Comp`、`/Role` 等标识 | 纯 ASCII |
| 日期 | PDF 日期格式 `D:YYYYMMDDHHmmSS+08'00'` |
| 长度 | PDF 结构里一律用 pt；`/Params` 里按参数定义的单位，多为 mm |

## 8. 版本与兼容

| 情况 | 处理 |
|---|---|
| 不认识的键 | 忽略，保存时原样保留 |
| 组件 `/Ver` 高于软件支持的版本 | 组件可以整体移动、删除，参数只读，不重算校验值；属性面板提示"需要更新软件才能修改" |
| `/Params` 不是合法 JSON，或缺少必填参数 | 按普通编组显示，图层面板提示"组件数据损坏，已按普通对象处理" |
| `/Hash` 不一致 | 图层面板提示，可按参数重新生成，或解散为普通对象（方案 11.4） |
| 文档级 `/Fmt` 高于支持版本 | 见第 3 节 |
| 其他软件删掉了 `EMC`，或打乱了嵌套 | 按 PDF 规范修复嵌套后读取；修复不了的序列当普通对象 |

升版规则：
- `/Fmt` 只在出现不兼容修改时才升，原则上不升。
- 组件参数结构有不兼容修改时升该组件的 `/Ver`，代码里保留从旧版本到新版本的迁移函数；用户修改旧组件参数时自动升级到新版本。

## 9. 本机数据文件

### 9.1 目录

| 路径 | 内容 |
|---|---|
| `%APPDATA%\MagPDF\templates\` | 模板 PDF 和 `index.json`（方案 10.2） |
| `%APPDATA%\MagPDF\components\` | 印章库、我的组件（v1.1）的单页 PDF 和 `index.json`（方案 11.8） |
| `%APPDATA%\MagPDF\settings.json` | 偏好设置，含各打印机的打印偏移 |
| `%LOCALAPPDATA%\MagPDF\recovery\` | 崩溃恢复文件（方案 9.3） |
| `%LOCALAPPDATA%\MagPDF\jobs\` | 任务进程用的文档快照（方案 3.3），任务结束即删除 |
| `%LOCALAPPDATA%\MagPDF\ocr-cache\` | OCR 结果缓存（方案 6.2） |
| `%LOCALAPPDATA%\MagPDF\logs\` | 日志和崩溃转储（方案 13.4） |

模板和设置放在漫游目录（`%APPDATA%`），用了漫游配置文件的公司电脑换机后仍在；缓存和恢复文件放在本地目录。

### 9.2 模板库和组件库的 index.json

```json
{
  "fmt": 1,
  "items": [
    {
      "file": "提单套打-SAMPLE.pdf",
      "sha256": "4f1c…",
      "name": "提单套打-SAMPLE",
      "category": "套打",
      "kind": "overlay",
      "rev": 3,
      "modified": "2026-11-06T19:30:00+08:00",
      "thumb": "thumbs/4f1c….png",
      "protected": false
    }
  ]
}
```

- index.json 只是缓存。条目的 `sha256` 和文件对不上，或 index.json 丢失时，从各 PDF 的 `/MagPDF /Template` 重建（方案 10.2）。
- 组件库条目多一个 `comp` 字段，记录组件类型。`protected` 为 true 表示设了密码的印章（9.3）。

### 9.3 设了密码的印章（P3）

设了密码的印章保存为 `.magseal` 文件，明文是印章的单页 PDF：

| 偏移 | 长度（字节） | 内容 |
|---|---|---|
| 0 | 8 | 魔数 `MAGSEAL1` |
| 8 | 4 | Argon2id 内存参数，KiB，小端 |
| 12 | 4 | Argon2id 迭代次数，小端 |
| 16 | 1 | Argon2id 并行度 |
| 17 | 16 | 盐 |
| 33 | 12 | AES-256-GCM 随机数 |
| 45 | 到文件尾 | 密文，末尾 16 字节是认证标签 |

- 密钥用 Argon2id 从密码派生，默认 64 MiB、3 次迭代、并行度 1。
- 同步到其他电脑的文件夹里不放 `.magseal`（方案 11.8）。

### 9.4 恢复文件

每个打开的文档一个子目录 `recovery\<会话 ID>-<文档 ID>\`：

| 文件 | 内容 |
|---|---|
| `meta.json` | 原文件路径、大小、修改时间、SHA-256；文档版本号、写入时间、软件版本 |
| `delta.bin` | 相对原文件的增量更新部分，即增量保存时会追加到原文件末尾的那些字节 |
| `base.pdf` | 只有没有原文件的文档才有，如从模板新建、尚未保存的"未命名-1" |

- 恢复时先核对原文件的大小和 SHA-256，一致才把 `delta.bin` 接在原文件后面载入。原文件被改过或被移走时，提示用户找回原文件或放弃恢复。
- 文档正常关闭或保存后删除对应目录。启动时发现残留目录，列为可恢复的文档（方案 9.3）。
- 任务进程的快照（`jobs\<任务 ID>\`）用同样的格式。

### 9.5 OCR 缓存

文件名是原 PDF 的 SHA-256 加 `.json`：

```json
{
  "fmt": 1,
  "models": { "det": "PP-OCRv5_mobile_det", "rec": "PP-OCRv5_mobile_rec", "ori": "PP-LCNet_x1_0_doc_ori" },
  "pages": [
    {
      "index": 0,
      "rotation": 0,
      "skewDeg": 0.4,
      "lines": [
        { "text": "SHIPPER", "conf": 0.98, "quad": [36.1, 790.2, 92.4, 790.0, 92.5, 779.8, 36.2, 780.0],
          "chars": [[36.1, 44.0], [44.0, 51.9]] }
      ]
    }
  ]
}
```

- 坐标是页面坐标，单位 pt。`chars` 是每个字的左右边界，供文字层逐字定位。
- 缓存里有文档的文字，属于敏感数据：默认上限 1 GB，按最近使用淘汰；90 天没打开过的文档，缓存自动删除；偏好设置里可以一键清空。
- 换了模型（`models` 不同）时缓存作废，重新识别。

### 9.6 settings.json

```json
{
  "fmt": 1,
  "ui": { "theme": "dark-2", "workspace": "货代单证", "unit": "mm" },
  "editor": { "historyLimit": 50, "recoveryIntervalSec": 120 },
  "ocr": { "autoStart": true, "writeOnSave": true },
  "templates": { "extraFolders": ["D:\\同步盘\\MagPDF 模板"] },
  "printers": {
    "EPSON LQ-630KII ESC/P2": { "offsetMm": [1.5, -0.8], "paper": "空运单 8.5×11in" }
  }
}
```

- `printers` 以 Windows 打印机名为键，保存打印偏移和上次的纸张（方案 9.4）。
- 不认识的键原样保留，降级到旧版本软件时设置不丢。
