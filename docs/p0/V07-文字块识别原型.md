# V07 文字块识别原型

P0 验证项 V07（《P0 技术验证计划》3.2）：把 PDFium 给出的字符按基线、字体、间距聚成行和段落，推断对齐方式和行距（方案 5.1 第 1 条）。本报告写原型的算法、参数依据、评测定义、在合成布局与公开样本上的观察、已知差距，以及正式 150 页评测前要做的准备。目标值：行的聚类正确率 ≥ 98%，段落 ≥ 90%。

代码：`engine/magpdf-text`（`#![forbid(unsafe_code)]`，纯几何计算，不依赖 PDFium 运行时；只有 `glyph.rs` 里的转换函数依赖 `pdfium-sys` 的类型），命令行 `magpdf-cli text-blocks`，标注格式见《V07-标注格式》。

## 1. 目标与范围

- 输入：一页的全部字符（Unicode、紧包围盒、基线起点、字号、字体、文字矩阵、是否 PDFium 生成、是否无 Unicode 映射、所属文字对象），加上页面上的细线路径包围盒（表格框线）。
- 输出：行（`Line`）与块（`Block`，即段落），每个带字形索引、包围盒、主字体与字号、基线角度、是否可编辑、是否不可见；块另带对齐方式（左 / 中 / 右 / 两端）、行距（点与 em）、是否水平。
- v1 只处理显示时水平（基线相对页面 `/Rotate` 为 0° 或 180°）的块；90°/270° 的块照常聚类但标记为非水平；其他角度（印章、水印、斜排表头）的字符按文字对象各成一行一块，标记为非水平。
- 不做：竖排（Identity-V）、从右到左的逻辑顺序、Type3 字号校正、跨栏续排（都在方案 5.5 的 P4 或 v1.1）。

## 2. 方法

### 2.1 输入类型与 PDFium 的对应

`PageText { width, height, rotation, glyphs: Vec<Glyph>, fonts: Vec<FontInfo>, rulings: Vec<Rect> }`，`Glyph` 与 PDFium 字符索引一一对应（生成字符也占位，保证索引可以直接用于标注）。`PageText::from_page` 从 `pdfium_sys::Page` 一次取齐；`push_char(&CharInfo)` 做单字符转换，单元测试直接构造 `PageText`，不需要 PDFium。

读 PDFium 源码核实的几个事实决定了转换方式：

- `FPDFText_GetFontSize` 是 `Tf` 的字号，`FPDFText_GetMatrix` 是文字矩阵 × 表单矩阵、**不含字号**。页面坐标系里的实际字号 = |Tf 字号| × hypot(c, d)，基线角度 = atan2(b, a)。
- 生成字符（词间空格、行末 `\r\n`）包围盒退化、没有文字对象、字号为 1，聚类时跳过，只保留索引。
- 没有 Unicode 映射的字符，PDFium 把字符码填进 Unicode 并置 `HasUnicodeMapError`；行末连字符 Unicode 为 2 并置 `IsHyphen`。
- 空格一类无轮廓的字符，PDFium 给零高度、宽度等于进距的包围盒。
- `FPDF_GetPageWidthF/HeightF` 已应用 `/Rotate`，字符坐标没有；`from_page` 换回内容流坐标系的尺寸并记下 `rotation`。

为此在 `pdfium-sys` 里补了几个只读能力（都有 `// SAFETY:` 注释和烟雾测试）：`CharInfo.unicode_map_error / hyphen / text_object_id / render_mode`，`TextPage::is_hyphen`、`text_object_id`，`PageObject::handle_id`（页内不透明标识）与 `text_render_mode`。没有改 `bindings.rs`。

### 2.2 行聚类（`layout/lines.rs`）

1. **分象限**：按基线角度把字形分到 0/90/180/270° 四组（容差 1°），其余角度按文字对象各成一行。每组把坐标旋转到规范坐标系（u 沿基线、v 垂直基线），之后的逻辑只写一遍。
2. **扫描**：按 v 降序、u 升序排序后单次扫描；维护一组"开放行"，当前字形的 v 低于某行基线超过 `baseline_tol_em × 字号` 时该行关闭。候选行须满足：基线差 ≤ 0.25em（以两者中较小字号计）、字号比 ≤ 2、与行尾的水平间距不超过上限、中间没有竖直细线穿过。多个候选取间距最小者。
   - 间距上限：不同文字对象之间 `max_word_gap_em = 1.5`；同一文字对象内放宽到 `same_object_gap_em = 3.0`（生成器把整行写进一个 `TJ` 时，大位移不应拆行；但两个对象之间 2.5em 的空隙是表单"标签 / 内容"，要拆）。
   - 排序保证每个字形只与"够得着"的开放行比较，整体接近 O(n log n)。
3. **上下标**：字号 ≤ 主行 0.8 倍、不超过 4 个字形、纵向与主行重叠、水平落在主行范围内（或紧挨行尾 0.5em）的小片段并入主行。
4. 行的主字号、主字体取众数；行内字形按 u 排序（视觉顺序）。

### 2.3 块聚类（`layout/blocks.rs`）

第一遍（贪心开放块）：行按 v 降序扫描，归入满足以下条件、且基线距最小的开放块：

- 水平重叠 ≥ 较窄一方宽度的 50%（`block_overlap_ratio`）；双栏因此不会互相并入。
- 基线距 ≥ 0.5em（更近的是并排片段），≤ 块内行距中位数 × 1.3（`pitch_tolerance`）；块还没有行距时用页面行距估计（对每行找正下方最近的同类行，取基线距 em 的众数，≥ 3 个样本才采信）× 1.3，估不出时用 `first_pitch_em = 1.8`；任何情况下 ≤ `max_pitch_em = 3.0`。
- 主字号与块首行之比 ≤ 1.15（`block_size_ratio`）；两行都是单一字体且字体族不同时不并（粗体标题与正文同字号也能分开）。
- 新行宽度不超过块宽的 2.5 倍（`width_growth_ratio`，窄表格列后面接整行正文）。
- 两行之间没有横向细线把它们隔开（细线须在上行基线下 0.3em 以下——排除下划线——下行字头以上，且横向覆盖两行重叠区的一半以上）。

第二遍在块内切分：行距跳变（> 中位数 × 1.3 且绝对差 > 0.15em）；首行缩进（左缘比块左缘靠右 > 1em）且上一行不满（右缘短 > 1em）；两端对齐块里上一行不满；行首是列表标记（项目符号，或 ≤ 3 个字母数字 + `.`/`)`/`、` 后跟空格或间隙）。

### 2.4 对齐与行距推断

- 行距：块内相邻基线距的中位数，同时给点值和 em（相对块主字号）。
- 对齐：n ≥ 3 时左边缘不看首行（允许缩进 / 悬挂）、右边缘不看末行（允许不满），容差 `align_tol_em = 0.4`。左右都齐时按首行是否缩进 / 外凸、末行是否满行区分两端对齐、右对齐、左对齐（所有行等宽时取左对齐，呈现上无差别）；只左齐→左；只右齐→右；中心齐→居中。单行块：中心与页面中心重合（且不是从左边距开始）才判居中，否则左对齐。
- 等宽汉字排满整行时左对齐与两端对齐无法区分，按两端对齐报告（中文公文与 Word 中文段落的默认值）。

### 2.5 可编辑与可见

- 块内有"无 Unicode 映射**且有可见字形**"的字符即不可编辑（方案 5.1 第 2 条）。无轮廓的未映射字符（文件里直接写进字符串的 `\r\n`、编码在 2 号位的空格——`rotated_text.pdf`、`bigtable_mini.pdf` 都有）不影响编辑，重排时按进距当空白；这是对方案条文的一个收窄，见第 7 节。
- 渲染模式 3/7 的字符标为不可见；整块不可见即扫描件的 OCR 文字层。

## 3. 参数与默认值依据

| 参数 | 默认 | 依据 |
|---|---|---|
| `baseline_tol_em` | 0.25 | 同行字符基线偏差一般 < 0.05em；上标抬高约 0.33em、下标下沉约 0.2em，上标须先被拆出再按"卫星"并回，否则会把基线拉偏 |
| `max_word_gap_em` | 1.5 | 词间距 0.25–0.35em；两端对齐拉伸后极少超过 1em；Word 默认表格两个相邻单元格之间最小 1.05–1.45em（左右各 0.19cm 单元格边距 + 空余）；项目符号到正文约 1.2em（同一对象或列表标记规则兜底） |
| `same_object_gap_em` | 3.0 | 同一个 `TJ` 里 2em 以上的位移多为制表位，少数生成器一行一个对象；表单"标签 / 内容"通常是两个对象 |
| `max_size_ratio_in_line` | 2.0 | 行内大写首字 / 货币符号放大通常 ≤ 1.5 倍；首字下沉另算 |
| `satellite_size_ratio` / `satellite_max_glyphs` | 0.8 / 4 | Word 上下标字号 0.65 倍、脚注编号 1–3 位 |
| `angle_tol_deg` | 1.0 | 原生 PDF 的旋转是精确的 90° 倍数；OCR 纠偏后的文字层另有角度，归入"其他角度" |
| `min_line_gap_em` | 0.5 | 上下两行基线距不可能小于字高的一半 |
| `block_overlap_ratio` | 0.5 | 两栏之间即使栏间距很窄重叠也是 0；缩进 2 字的首行与正文重叠 ≥ 0.9 |
| `pitch_tolerance` | 0.3 | Word 单倍行距 1.17–1.32em，段后 8pt 使段间基线距达到 1.9–2.05em，比 1.3 倍行距（1.5–1.7em）大；固定 28pt 行距的公文段间无空行时靠缩进规则 |
| `first_pitch_em` / `max_pitch_em` | 1.8 / 3.0 | 页面估不出行距时第一对行允许到 1.8em（覆盖 1.5 倍行距），绝不超过 3em（双倍行距 2.3em 以内） |
| `block_size_ratio` | 1.15 | 标题最小一级比正文大 1.2 倍（Word 标题 3：12pt 对 11pt 是 1.09——这种情况靠粗体 / 字体族区分） |
| `width_growth_ratio` | 2.5 | 表格窄列（≤ 10 字）下面接整行正文（≥ 40 字） |
| `indent_em` / `ragged_em` | 1.0 / 1.0 | 中文首行缩进 2 字、英文 0.5 英寸 ≈ 3em；段末短行通常短一个词以上 |
| `align_tol_em` | 0.4 | 两端对齐的行尾差 < 0.1em；左对齐行尾参差至少一个词 |
| `ruling_max_thickness` | 2.5pt | 表格框线 0.5–1.5pt，装饰粗线 ≥ 3pt |

全部参数 `serde(default)`，`magpdf-cli text-blocks --params 参数.json` 可以只给要改的字段，正式评测时用来做参数扫描。

## 4. 评测定义

见《V07-标注格式》第 4 节。主指标是**字符一致率**（预测簇与标注簇互为最大重叠才算对；拆与并都按字符数受罚），辅助指标是**完全匹配率**。`magpdf-cli text-blocks 样本.pdf --labels 样本.labels.json` 逐页输出并汇总；`--emit-labels` 生成预标注。评测函数本身有 8 个单元测试（满分、拆行、并行、未标注字符忽略、多页汇总等），并用故意改坏的标注验证了命令行的数值：把一行从中间拆开、把两段合并后，行字符一致率 98.9%、段 86.1%，与手算一致。

## 5. 样本与结果

### 5.1 合成布局（单元测试，`layout/tests.rs`，21 个）

用一个简易排版器（等宽近似：拉丁 0.5em、数字 0.55em、空格 0.28em、汉字 1em）构造 `PageText`，断言行 / 块 / 对齐 / 行距：

### 5.3 耗时

- 合成 10 800 字形页：聚类 **1.1 ms**（release，20 次平均；debug 4.6 ms）。满足"万字页几十毫秒"的要求两个数量级。
- `annotation_stamp_with_ap.pdf`（1073 字符）：PDFium 提取 0.9 ms + 聚类 0.16 ms（release）。提取耗时主要在 PDFium 逐字符的 FFI 调用（每字符十余次，含两次取字体名），之后按需合并成批量接口。

## 6. 结论

- 算法在合成布局和手头的公开样本上行、段都没有错分，推断的对齐与行距与文件实际版式一致；性能余量很大。
- 公开样本文字量太小（最多 1073 字符一页，没有货代单证），**不能据此宣称达到 98% / 90%**。正式评测需要按第 8 节准备 150 页标注样本后用同一套命令跑。
- 评测脚手架（标注格式、两种正确率、预标注、参数文件）已经可以支撑标注与参数扫描。

## 7. 偏离方案之处

1. **"不可编辑"的判定收窄**：方案 5.1 第 2 条说"没有 Unicode 映射的文字标记为不可编辑"。原型只在未映射字符**有可见字形**时才标不可编辑；无轮廓的未映射字符（控制码、怪异编码的空格）按空白处理。否则 `bigtable_mini.pdf` 这类一行 64 字因一个空格而整块锁死。建议写进方案。
2. **行的定义包含表格拆分**：方案只说"按基线、字体、间距聚类为行"，原型明确把同基线上间距 > 1.5em 的两个文字对象当作两行（单元格、表单标签 / 内容），并用竖直细线辅助。标注格式据此定义"行"。
3. **非水平文字**：方案 5.5 把竖排和 RTL 放在 P4；原型额外把 90°/270° 的块与任意角度的文字对象也标为非水平，v1 对它们只做整体变换。
4. **页面 `/Rotate`**：方案没有提及；原型把"水平"定义为相对显示方向，并记录内容流坐标系里的角度供编辑时写回。

**算法已知差距**

- Type3 字体的字号（`bug_1591.pdf`）：用每个字体的字形包围盒高度中位数校正 `font_size`（或读 PDFium 的字体包围盒 × 字体矩阵）。P4 之前至少要让这类页面不把全页并成一行。
- 竖排、RTL：按方案在 P4；行内字形顺序目前是视觉顺序，写回文字对象前要按文字对象内的原索引顺序。
- 只含空格的行 / 块（`vertical_text.pdf`）：是否把纯空白行并入最近的块或从输出中剔除，取决于 V08 的编辑模型，先保留。
- 单行块的居中判定只看页面中心；表格单元格里的居中、右对齐数字列要结合框线或列边界，留给表格识别。
- 列表标记规则只认 ASCII / 全角标点和 "一二三…"，货代单证里的 "①②"、"(a)" 已覆盖，"第 X 条" 没有。
- 页面行距估计以众数代表全页；标题密集的页（众数不是正文行距）第一对行的上限会偏松或偏紧，目前靠 `first_pitch_em` 兜底。

**工程**

- `PageText::from_page` 逐字符 FFI；150 页评测时如果提取耗时显著，再给 `pdfium-sys` 加批量接口。
- `text_of` 只用于调试与预标注备注；日志里没有也不要加入文档文字。

**正式评测准备（150 页）**

1. 样本：按 V07 要求 Word / WPS 导出 100 页（覆盖：单倍 / 1.5 倍 / 固定行距、首行缩进、段前段后、两端对齐、多级标题、项目与编号列表、两栏、带框线与无框线表格、页眉页脚），货代单证 50 页（提单、装箱单、发票、报关单——表格为主，标签 / 内容对）。每页 `manifest.csv` 打 `text-labels` 标签。
2. 标注：`--emit-labels --with-text` 预标注 → 人工修正 → 删备注 → 10% 复标互评（行 ≥ 99%、段 ≥ 95% 才算标注合格）。预计每页 5–10 分钟。
3. 评测：`text-blocks --labels --json`，按来源（Word / WPS / 单证）和特征（表格、双栏、列表）分组汇总字符一致率与完全匹配率；用 `--params` 扫 `max_word_gap_em`（1.2–2.0）、`pitch_tolerance`（0.2–0.4）、`block_size_ratio`（1.1–1.25），看指标是否对参数敏感。
4. 失败分析：对每个一致率 < 90% 的页输出 JSON 与渲染图对照，归类为"算法规则缺失 / 参数 / 标注歧义"。
