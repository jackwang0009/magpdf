每帧的执行顺序（`CanvasController.render`）：`computeRenderPlan()` → 把缺失瓦片优先队列交给 `TileScheduler` → `GlTileRenderer.draw(plan)`（已就绪的瓦片 + 跨档回退 + 页底色）→ `drawOverlay(...)`。渲染计划里的任何数字都可以在不需要浏览器的情况下断言。

### 1.2 每帧渲染计划（`renderPlan.ts`）

输入：`PageLayout`、视图 `{zoom, x, y}`、视口 CSS 尺寸、`devicePixelRatio`、`has(id)` 缓存查询。
输出：

- `pages`：与视口相交的页（`PageLayout.visiblePages` 二分，300 页是 O(log n)）；
- `targetLevel`：显示比例（zoom × 96/72 × DPR）对应的最小瓦片档（`pickLevel`，13 档，√2 递进，宁可多渲染不放大模糊）；
- `tiles`：目标档已缓存的瓦片四边形（设备像素坐标）；
- `fallback`：目标档缺失时，从更粗档位取已缓存瓦片按原比例拉伸（先粗后细，保证不出现白块）；
- `missing`：需要请求的瓦片，按“离视口中心的距离 / 档位”排队；
- `prefetch`：视口上下各一屏的瓦片，优先级低于缺失。

### 1.3 工具与选区状态机

`selectTool` 的状态：`idle → pressed → (marquee | moving | pressedHandle → scaling | rotating)`，全部转移是纯函数，返回 `ToolEffect[]`（`setSelection`、`moveObjects`、`resizeObjects`、`deleteObjects`、`setView`、`overlay`、`cursor`）。点击、Shift 加选/减选、框选（相交/包含两种模式）、拖动移动、8 控制点缩放、角外侧旋转、方向键微移（0.1 mm，Shift ×10）、Delete、Esc 都由状态机完成。

`ToolManager` 的补充约定：

- 按住 Space 临时切抓手，抬起后恢复；若拖动中抬起按键，等指针抬起再恢复；
- 中键拖动平移，不改当前工具；
- 同一次手势内（`pointerdown` 到 `pointerup`）工具自己改过的选区立刻对后续事件生效（`selectionOverride`），不依赖 store 下一帧渲染；store 里的选区被外部改动（图层面板、删除对象）时调用 `forgetSelectionOverride()` 作废。

## 2. 工作区与布局

内置两个工作区（`workspace/workspaces.ts`），切换在「窗口」菜单，选择会记在 `localStorage`：

| 工作区 | 组件面板 | 右侧 | 用途 |
| --- | --- | --- | --- |
| 货代单证（默认） | 展开 240px（可拖 200–320） | 右上：属性、字符、段落；右下：图层、页面、历史记录、导航器 | 界面图 8.2 |
| 基础 | 折叠成 32px 图标条 | 一个组：属性、图层、页面、历史记录 | 通用文档 |

布局细节：

- 工具栏**不是** dockview 面板，是外壳顶部的一行普通横条（菜单栏下方、与选项栏同一行 36px）：7 个工具横排在左，工具选项跟在后面，填充/描边色块在行尾；它参与外壳布局、不浮动、不盖住组件面板或画布。旧版把它做成 dockview 浮动面板（宽 40，贴左边距 0 / 上边距 40）会盖住东西，已改掉；
- 右侧 32px 图标条是网格里的一个固定宽度组（`maximumWidth = minimumWidth = 32`、隐藏标签头），点图标把对应面板浮到右侧；
- 组件面板折叠时组宽锁 32px、`locked: 'no-drop-target'`，展开时约束 200–320px；右侧组（右上、右下、基础的右侧组）同样约束 200–320px，拖分隔条不能超出这个范围；
- 容器尺寸变化由 `ResizeObserver` 调 `api.layout(w, h)`（`disableAutoResizing`、`proportionalLayout: false`），文档区吸收宽高变化，两侧保持宽度；
- 布局变化 500ms 防抖后 `captureWorkspace()` 回读并写入 `localStorage`（去掉文档面板和图标条；旧版浮动工具栏的残留也会去掉），下次启动恢复；保存时网格里也不留文档面板的视图，视图已空的非结构组在保存和加载时都丢弃（`cleanDockviewLayout()`），只保留组件、文档、右侧这几个结构组；两侧宽度超出 200–320px 的保存值在保存和加载时都收进范围（`clampSideWidths()`），下次加载自动生效；
- 「窗口 → 复位工作区」清掉保存值并回到内置布局；「窗口 → 切换组件面板」等价 Tab 键隐藏/显示整个工作台。

> 说明：切换工作区时 `fromJSON` 之后需要重新登记右侧图标条，`applyWorkspace()` 里用 `ensureStrip()` 保证它一定存在。旧版的 `ensureToolbar()`（浮动工具栏）已删除：工作区布局版本从 1 升到 2，旧版 v1 保存值解析为无效、自动回落到内置布局；`applyWorkspace()` 还会在 `fromJSON` 之后丢弃残留的工具栏面板。加载时 `applyWorkspace()` 先用 `cleanDockviewLayout()` 清掉保存值里残留的文档视图和空组再 `fromJSON`：dockview 8.8.3 在 `fromJSON` 时会跳过面板表里没有的视图、把组留空，`closeEmptyGroups={false}` 时空组不自动消失，只显示“没有打开的文档”水印，旧保存值里的空组会在刷新后复活，所以保存和加载两边都要清。P0 没有做“拖出/合并面板”的自定义布局测试，但 dockview 自身的拖放是开启的，保存的 JSON 会包含浮动组。

## 5. 帧时间：方法与数据

### 5.1 方法

- 构建：`pnpm dev`（Vite 8.3.6，未压缩，React 开发构建），Microsoft Edge 156（`channel: 'msedge'`），窗口 1600×1000，DPR = 1，`--disable-background-timer-throttling`。
- 文档：「文件 → 新建 → 300 页测试文档」（`createMockDocument` 的 `report` 模板，每页约 60 个文字/路径/图像占位对象，A4）。
- 视口：货代单证工作区、1600×1000 窗口下文档区约 380×863 CSS px；读屏缩放 = `zoom × 96/72 ≈ 1.6`（A4 页宽略超出视口）。
- 瓦片：目标档按 `pxPerPt = zoom × 96/72 × DPR` 选取（缩放基准约 2.13 → 档 7，256px 瓦片），DOM 上只有一块 WebGL2 画布 + 一块等大 2D 叠加层。
- 每个阶段连续 240 帧，`requestAnimationFrame` 中先执行操作（平移/缩放/跳页）、`invalidate()` 再等下一帧；`FrameStats` 记录相邻帧间隔与每帧脚本工作时间（`performance.now()` 前后差）。
- 统计：分位数用最近秩法（`percentile()`），长帧阈值 16.7 ms；`intervalMax` 是该阶段最大帧间隔，`workMax` 是最大脚本时间。
- 开关：状态栏右侧按钮 /「视图 → 显示帧时间」，最近 240 帧的 P50/P95/脚本 P95 实时显示；「视图 → 运行性能基准」或控制台 `__magpdf.benchmark(240)` 跑完整 4 阶段并把结果 JSON 打到控制台。基准入口只在开发构建（`import.meta.env.DEV !== false`）挂到 `window.__magpdf`。

阶段定义（`canvas/benchmark.ts`）：

| 阶段 | 操作 |
| --- | --- |
| `pan-slow` | 读屏缩放下，每帧 ±12 px 上下交替滚动（模拟滚轮/触控板） |
| `pan-fast` | 每帧向上 80 px，瓦片持续缺失，考验渐进显示与调度 |
| `zoom` | 以视口中心为锚点，1/4 ↔ 4 倍正弦往返两次（每帧 `zoomAtPoint`） |
| `jump` | 每帧 `scrollToPage` 跳到后 6 页（页面面板点击、拖动滚动条），缩放不变 |

### 5.2 环境与干扰

- CPU：AMD Ryzen 7 9800X3D；测量期间系统总 CPU 占用 31%–44%（另有 agent 在编译，`node` 进程 15 个），GPU 为 Edge 内置软件/硬件混合渲染（`RENDERER = WebKit WebGL`）。
- 浏览器输出：控制台 0 条 error / warning（含 React 嵌套按钮警告与 favicon 404 均已修复）。
- 两次测量（较早一次 CPU 32%–67%，正式一次 31%–44%）各阶段 P50/P95 相差不超过 0.2 ms，下面记录正式一次；本机刷新率 100 Hz（P50 = 10.0 ms 即“每帧都赶上了”）。

### 5.3 结果（300 页，240 帧/阶段）

| 阶段 | 样本 | 帧间隔 P50 | 帧间隔 P95 | 帧间隔最大 | 脚本 P50 | 脚本 P95 | 脚本最大 | 长帧(>16.7ms) |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| pan-slow | 239 | 10.0 ms | 10.1 ms | 20.1 ms | 0.3 ms | 1.5 ms | 8.1 ms | 7 |
| pan-fast | 239 | 10.0 ms | 10.1 ms | 30.0 ms | 0.3 ms | 2.6 ms | 10.9 ms | 7 |
| zoom | 239 | 10.0 ms | 10.1 ms | 20.1 ms | 0.3 ms | 1.9 ms | 8.0 ms | 8 |
| jump | 239 | 10.0 ms | 19.9 ms | 40.0 ms | 0.3 ms | 8.7 ms | 12.0 ms | 12 |

瓦片统计：完成 627 次渲染、取消 276 次、过期丢弃 0 次；缓存 598 块 / 96 MB（上限 96 MB，LRU）；MockTileProvider 平均每块 0.06 ms。

解读：

- 平移与缩放：P95 10.1 ms，脚本 P95 ≤ 2.6 ms，远低于 60 fps 的 16.7 ms 预算；长帧 7–8 次集中在阶段切换的第一帧（新一屏瓦片排队）。
- 跳页：每帧换到全新一屏，P95 19.9 ms 说明约 5% 的帧掉到 10 Hz 档；脚本 P95 8.7 ms 是排队的 20–24 块瓦片在 Mock 渲染上的时间，真实引擎（PDFium 单线程、方案 3.3）下这部分会迁移到引擎进程，界面侧应只显示缩略图/白底占位，因此正式接入时以“不阻塞主线程”为准，实测数值不能直接外推。
- 真实 GL 纹理上传在浏览器里无法从 JS 侧计时，故表中“脚本时间”不含 GPU 上传与合成；Mock 的 0.06 ms/块只代表 2D 画位图的开销。

复现：`pnpm dev` → 打开 300 页测试文档 → 控制台执行 `await __magpdf.benchmark(240)`，或「视图 → 运行性能基准」在对话框里看表并「复制 JSON」。

## 6. TileProvider 接口（给 V06 引擎对接）

`packages/editor/src/canvas/tileProvider.ts`。画布**只**通过这个接口取位图，Mock 与真实引擎共用同一套调度与缓存。

```ts
interface TileRequest {
  page: number;            // 页号，从 0 开始
  level: number;           // 缩放档 0..12，pxPerPt = 96/72 × 2^((level-6)/2)。缓冲缓存与纹理都按 (page,level,tx,ty) 索引
  pxPerPt: number;         // 该档的渲染分辨率（设备像素/pt），level 的冗余参数，便于实现直接取 dpi = pxPerPt × 72
  tx: number; ty: number;  // 瓦片在整页位图中的列、行（0 起）
  tileSize: number;        // 瓦片边长，当前 256（设备像素）。边缘瓦片 = 页面剩余部分
  pixelRect: Rect;         // 该瓦片在整页位图中的像素矩形 {x,y,width,height}；= {tx*256, ty*256, ≤256, ≤256}
  pageRect: Rect;          // 同一区域换算到页面坐标（pt），便于引擎直接按 pt 渲染
  documentVersion: number; // 调度器当前的文档版本；与结果返回时版本不一致会被丢弃
  signal: AbortSignal;     // 取消信号
}

interface TileResult {
  width: number;           // 必须等于 pixelRect.width
  height: number;          // 必须等于 pixelRect.height
  pixels: ImageBitmap | { data: Uint8Array | Uint8ClampedArray; width; height }; // 不透明 RGBA，行主序、无行填充
}

interface TileProvider {
  renderTile(request: TileRequest): Promise<TileResult>;
  readonly concurrency?: number; // 建议 1–2（PDFium 串行）；排队放在界面侧，视图移动后能按新优先级重排
  dispose?(): void;
}
```

调用约定（V06 实现时必须遵守）：

1. **代数**：`documentVersion` 在编辑提交后递增（`DocumentSnapshot.version`）。调度器在每个批次（每次 `setWanted`）记录当时的版本，返回时版本已变则直接释放结果、计入 `stale`，不进缓存。实现不需要自己比较版本，但**不要**缓存上次结果冒充新版本。
2. **取消**：`signal` 在三种情况触发——瓦片离开“想要的列表”（视图移走）、该页被 `invalidatePage`（对象修改）、调度器销毁。实现应尽早放弃计算并以 `name === 'AbortError'` 的错误拒绝（`AbortError` / `isAbortError()` 已导出）；即使拒绝得晚，调度器也会丢弃并释放像素。若引擎侧是消息队列，取消消息只需要是“丢弃该 token 的结果”，不必真正中断 PDFium。
3. **尺寸**：结果宽高必须严格等于 `pixelRect` 的宽高，否则渲染器按最近邻缩放会出现接缝；`pixels` 用 `ImageBitmap`（推荐，`createImageBitmap` 后渲染器直接 `texImage2D`，用完 `close()`）或裸 RGBA 都可以。
4. **并发**：界面侧默认并发 = `provider.concurrency ?? 3`；PDFium 单线程时给 1 或 2，把排队留在界面（`TileScheduler` 每次视图变化都会重排队列，慢的旧请求先被取消）。
5. **视口与预取**：`renderPlan` 只请求可见页的缺失瓦片与上下各一屏的预取瓦片；实现可以据此估算内存。缓存上限 96 MB（LRU，按字节），淘汰时释放 GPU 纹理，`ImageBitmap` 需 `close()`（`releasePixels()` 已封装）。
6. **失败**：`renderTile` 抛出非 Abort 错误时调度器记 `failed` 并在控制台输出 `瓦片渲染失败 <id>`，不会让该瓦片永久卡住——下一次 `setWanted` 会重新请求。建议引擎对同一瓦片连续失败 3 次后返回白底位图，避免死循环。
7. **页面尺寸变化**：页面尺寸来自 `DocumentSnapshot.pages[i]`（pt），若编辑改了页尺寸，调用 `invalidatePage(i)` 清缓存，调度器下次会按新 `pixelRect` 重新请求。

替换方式：`CanvasController` 构造时传入 `TileProvider`；当前 `TileCanvas` 用 `MockTileProvider`。V06 只需实现 `renderTile` 并在创建控制器时传入，无需改渲染器、缓存、调度器与叠加层。

## 11. 补记：在真实文档上选择和修改（2026-11-11）

第 10 节末尾说的“下一步”做了：真实 PDF 的对象列表进了界面，能点选、框选、拖动、拖控制点缩放、方向键微移、删除、撤销、重做，改完页面重画。引擎和协议那一侧、延迟的实测、端到端测试的结果见 V06 报告第 12 节，这里记界面这边。

### 11.1 修改怎么走

```
选择工具（状态机，没有变）
  └ 产生“移动 / 缩放 / 删除”这样的副作用
画布控制器
  ├ 文档有修改入口（DocumentEditor，宿主给的）→ 交给它；Ctrl+Z、Ctrl+Shift+Z 也交给它
  └ 没有（模拟文档）→ 照旧直接改 store 里的快照
EngineSession 里的修改入口
  ├ 先按预期把对象的包围盒挪过去，不等引擎
  ├ 命令排队，一条一条发，每条带上一条之后的版本号
  ├ 引擎推送 doc.changed → 重新取这一页的对象，以引擎的为准；这一页的瓦片重画
  └ 引擎不接受 → 重新取对象（界面恢复原状），告诉用户原因
```

- **对象按需取。** 打开时只有页面列表。看到一页（和它前后各一页）时才取这一页的旋转、可见区域和对象列表，对象多的页分批取（每批 2000 个）。几百页的文档打开时不用全部加载。
- **坐标换算。** 引擎给的包围盒在 PDF 用户空间里（y 向上、不含页面旋转），界面用的是页面坐标（左上角为原点、y 向下）。`pageSpace.ts` 管两边的换算，四种旋转、可见区域不从原点开始都算；发给引擎的变换矩阵也在这里换回用户空间。
- **缩放**交给引擎的是一个矩阵：把选区原来的外框映到现在的外框。多选时各对象的相对位置不变。
- **撤销记录在引擎里**（方案 4.2）。没有可撤销的操作时按 Ctrl+Z 什么也不发生，也不提示。
- 修改在途的时候，晚到的对象列表先不用，等这一页的修改都有了结果再取一次。否则连着改两下，第一下的对象列表回来会把第二下先挪过去的对象拉回原处。
- 界面记的版本号落后时（引擎报版本冲突），问一下现在的版本再发一次，不打扰用户。
- 引擎标了“点选时不算数”的对象（不可见文字、全透明对象、整页白底）在画布上点不中、框不中，仍然列在图层面板里。

和第 1.3 节相比，工具状态机只多了一个状态（11.3 的“拖不动”），其余没有动：它产生的副作用原来就不依赖数据从哪里来。

### 11.2 瓦片：新的画好之前，旧的先留着

原来的做法（第 6 节第 2、7 条）是页面一变就把这一页的缓存清掉重新要。模拟文档的瓦片是当场画出来的，看不出问题；引擎的瓦片要几十毫秒才到，这样做每改一下，这一页就先露出白底、等新瓦片到了才有内容。

- 页面变了以后，缓存里这一页的瓦片标成“旧的”，继续显示；同时重新请求，新的到了再换掉。
- 页面快照带一个修订号，只有修订号变了才重画。换对象列表（界面先挪、引擎再确认）不触发重画。
- 调度器不再比较文档版本号，改成按页作废：这一页在途的请求中止。别的页改了不影响这一页的瓦片。
- 顺带修了一个记数的错：被中止的请求原来会被数两次。只影响基准里的统计，不影响显示。

### 11.3 只能叠加内容的页

保真校验没通过的页（方案 2.3；为什么会有这样的页见 V06 报告 12.2）只能在上面添加内容，原有的对象不能改。引擎把结论推过来之后，界面这样表现：

| 位置 | 表现 | 依据 |
|---|---|---|
| 文档面板顶部 | 提示条：“第 1 页无法安全修改原有内容：页面使用了软件尚不能完整保留的效果。可以在这一页上添加内容。”悬停显示引擎给的具体原因。几页都是这样时列出页码，超过三页写“等 N 页” | 《交互设计》9.1、9.3 |
| 画布 | 对象照常能点选、框选。选框没有控制点，没有旋转热区；按住拖的时候对象不跟着走，光标是“不行”；方向键、Delete 不起作用 | 方案 2.3 |
| 属性面板 | 顶部一行说明：所在的页无法安全修改原有内容，属性只能查看 | 《交互设计》5.3 |
| 页面面板 | 这一页的行上有一个角标，悬停说明 | 《交互设计》5.4、方案 8.6 |

- 选区里只要有一个这样的对象，整个选区都不能动。
- 不弹对话框。第一版是引擎拒绝之后弹一个“出错了”的框，这不对：这是文档的状态，不是一次操作出了错，而且用户每拖一次就弹一次。
- 引擎是在页面显示之后抽空校验的，用户有可能赶在结论到之前就动手。这时界面先把对象挪过去，引擎拒绝，对象回到原处，提示条随后出现。
- 截图：`tests/out/e2e/smoke-4-overlay-only.png`（端到端测试每次运行都会重新生成）。

和文档有出入、或者还没做的：

### 11.4 用真实的按键查出来的两个问题（已修）

端到端测试的修改这一段用的是真实的鼠标键盘事件。第 10 节那一次查出的是“鼠标事件到不了画布”，这一次是键盘：

**焦点在文档标签页上时，按 Delete 会关掉文档。** dockview 给标签页配了自己的键盘操作：焦点在标签上时，方向键把焦点挪到旁边的标签，Delete、Backspace 关掉有焦点的那个标签。用户点过文档标签之后焦点就留在标签上——在画布上点选对象不会把焦点拿走——这时选中一个对象按 Delete，对象删掉了，一份文档也跟着被关掉，不问一声；按方向键微移，标签上的焦点也跟着跑，之后 Delete 关掉的可能是另一份文档。文档有没保存的修改时，这就是丢数据。现在焦点在标签页上时，这几个键只交给编辑器，dockview 收不到。代价是“焦点在标签上时用方向键换标签”没有了；文档之间怎么用键盘切换，《交互设计》第 8 节还没有定。

**切换工作区会把打开的文档全部关掉。** 工作区切换时要把整个布局重排一遍，文档面板先全部拿掉再按 store 重建。“面板被拿掉”的回调是给“用户关了标签页”用的，它不分这两种情况，于是把 store 里的文档也关了；对引擎打开的文档，这会让引擎真的把文档关掉，没保存的修改一起丢。在桌面程序里验证过：点一下选项栏右端的工作区按钮，打开的文档全部消失。这两段代码从 V12 合入起就在，原来没有用例在切换工作区之后看文档还在不在。现在重排期间不理会这个回调。

两处各有一条用例（jsdom 里对着真实的 dockview），都做过变异检查：去掉修复，用例失败。

## 12. 补记：组件原型——文本和 Code 128（2026-11-23）

组件面板原来只是摆样子：点了没反应，也拖不到页面上，选中对象时属性面板也不显示组件参数。这次先做一个小原型，只有两种组件，参数也只有两项，走通“放上去—选中—改参数—重新生成”这一圈。方案第 11 节的其余组件（日期、序号、QR、印章……）P1 起做，在面板里是灰的，悬停提示“P1 提供”。

### 12.1 用起来是什么样

- **放上去**：在组件面板里点“文本”或“Code 128”，按钮亮起，光标变成“复制”，状态栏提示“点页面放置……，Esc 取消”；再点页面，组件的左上角就在点的位置。也可以直接把按钮拖到页面上，松手的位置是左上角。点在页面外面不算，还在放置状态；右键不放。
- **放好之后自动选中**，属性面板多一段“组件参数”：类型、内容、字号（文本）或条高（条码），单位 pt。回车或离开输入框时生效；Esc 恢复原值。参数不合法时输入框标红，下面写明哪里不对（比如“Code 128 只能编码英文字母、数字和常见符号”），不发命令。
- **改参数**由引擎按新参数重新生成一个对象换掉旧的（方案 11.4），编号不变，左上角不动。
- 组件和别的对象一样能拖、能缩放、能方向键微移、能删除、能撤销；图层面板里叫“Code 128 · 内容”，状态栏显示“已选 1 个组件（Code 128）”。
- **只能叠加内容的页（11.3）上也能放、也能改**。页面原有的对象照旧不能动；选区里混着原有对象时整个选区不动。

截图：`tests/out/e2e/components-placed.png`（端到端测试每次运行重新生成）。

### 12.2 引擎那一侧

- **组件就是普通的页面对象**，参数存在它的标记内容里：`/MagComponent << /type (code128) /content (…) /size (36) >> BDC … EMC`。存盘再打开、列对象时从标记内容读回参数，所以图层面板、属性面板认得出来。文本是一个文字对象（标准字体 Helvetica，不嵌入），条码是一个路径对象（每根条一个矩形子路径）。代码在 `engine/magpdf-engine/src/component.rs`。
- **Code 128 是自己编的**：全是数字且位数为偶数时用 C 码集，否则 B 码集，模块宽 1 pt。方案定的是 Zint（`magpdf-components`），原型没有接。用 ZXing 识别引擎画出来的 9 组条码（包括 ASCII 32–126 全部 95 个字符、C 码集、首尾空格），全部识别正确：`tests/prototypes/components/check_code128.py`。
- **新加的对象不受保真校验限制**。编辑会话记下本次新加的对象；改它们时不校验它们所在的页。依据：PDFium 把新对象写进一条追加的内容流，之后只重新生成这一条，页面原有的流不动。用例照这一点核对过：两页共用一条内容流（流级检查必定判为只能叠加），在第 1 页上放条码、移动、改参数之后存盘，共用的那条流解码后逐字节不变，第 2 页的画面不变，第 1 页组件以外的地方像素不变。
- 撤销记录多了两种步骤：插入（删除的反过来）和替换（把页面上的对象和手里的那一个对调，正着、反着做都是对调）。

协议上加了 `comp.place`、`comp.update`，对象摘要多了 `comp`（类型和参数）和 `added`（本次新加的），参数不合法报 5001 `E_COMP_INVALID`、`data.checks` 标出是哪个参数。和《接口协议》6.7 的出入记在它的 12.2–12.4。

### 12.3 界面那一侧

- store 多了“正在放置哪个组件”。画布控制器在放置状态下把左键按下当成“放在这里”，不交给工具；拖放只接组件面板拖出来的（自定义的数据类型），文件、文字一概不接。Esc 先取消放置，没在放置才是取消选择。
- 引擎打开的文档：界面不先画，等引擎生成之后随 `doc.changed` 重画、重新取对象；新对象出现在列表里时选中它。模拟文档：直接在快照里加一个按参数估算大小的对象，模拟渲染画出来。
- “这个对象能不能改”的判断（工具状态机的 `hasFrozenObject`、引擎会话、属性面板的只读提示）都改成：页只能叠加内容，并且对象不是新加的。
- 组件参数的检查界面和引擎各做一遍，规则相同：界面那一遍是为了输入时马上提示，引擎那一遍是为了不信任界面。

### 12.4 端到端测试查出来的问题（已修）

**改完参数点回画布，方向键、Delete 不起作用。** 画布按下鼠标时 `preventDefault`（不让浏览器开始选中文字、拖图片），副作用是焦点留在原处：属性面板的输入框还拿着焦点，之后的按键都算在输入框里，全局快捷键按规矩不处理输入框里的按键。现在点画布时先让输入框失焦，正好也是“离开输入框就生效”。端到端测试的第 3 步（改完内容点条码再按右方向键）就是这样查出来的；补了一条单元用例。

**文字改一次参数往下漂一截。** 改参数时新对象对齐旧对象包围盒的左上角，条码的包围盒左上角就是放置的位置，文字的不是：文字放置时基线在锚点往下一个字号处，包围盒顶边却在字形上（约 0.72 个字号高），每改一次往下漂约 0.28 个字号，改五次漂了 19 pt。这是提交之前自查代码时发现的，用例和端到端测试都只改过条码。现在按旧参数在原点生成一份量出包围盒相对锚点的偏移，减回去得到锚点再生成；补了用例（改五次内容、换字号再换回来，位置不变）。

### 12.5 留给保存功能的问题

PDFium 存成完整的新文件时，**不再被引用的对象也照样写出去**。组件改参数后旧对象所在的那条内容流空了，PDFium 把它从页面的 `/Contents` 里拿掉，但没有删掉这个对象；撤销置入也一样。存出来的文件里，旧的组件内容（比如改之前的运单号）还在，只是看不见。现在的桌面程序还没有“保存”（`doc.save` 没有实现），用户碰不到；做保存时要把没有引用的对象去掉，否则这是一个泄露旧内容的口子。（同日补记：保存做了，存的时候只留引用得到的对象，见 V06 报告第 15 节。）

### 12.6 原型的限制

- 只有两种组件、两项参数。没有可读文字（条码下面的数字）、静区标示、码制选择、模块宽度、颜色；没有 `comp.schema`、`comp.validate`，参数界面是写死的。
- 文本只能写 ASCII：标准字体不嵌入、只有 WinAnsi 编码，中文要走 V08 的嵌入和子集化，没有接。（同日补记：接上了，见 12.8。）
- 改参数时只保留放置的位置（条码是左上角，文字是基线往上一个字号处的那一点，按原样平移过的也算），用户做过的缩放、旋转不保留。旋转过的页上，组件按 PDF 用户空间摆正，显示出来跟着页面转。
- **写进文件的格式故意和规范不一样。**《文件私有数据格式规范》4.3 规定组件是 `/MagPDF << /Comp /Ver /Params /M /Hash >>` 的标记内容，类型和参数按《组件参数定义》（Code 128 是 `barcode1d`，参数有码制、模块宽度、可读文字等）。原型的参数对不上那套结构，所以另用 `/MagComponent` 这个名字，免得原型存出来的文件以后被当成正式的组件读进来。P1 做组件时按规范的格式写，原型的这个名字不用再认。版本号、校验值（方案 11.4 的 `hashOk`）也都没有。

### 12.7 测试

- 引擎：编码表、校验位和码集选择、参数检查；置入、改参数、移动、撤销重做；文字改几次参数不漂；存盘再打开参数还在（内容里有括号、反斜杠）；只能叠加内容的页上不碰原有内容（见 12.2）。引擎进程：经管道走一遍 `comp.place`、`comp.update`、`E_COMP_INVALID`、撤销。
- 前端：组件面板（点、再点、拖出去带的数据、灰的按钮）、画布（点页面放置、页面外不算、右键不放、拖放只接组件、点画布时输入框失焦）、引擎会话（坐标换算、选中新对象、只能叠加内容的页上能改组件不能改原有对象、错误提示、撤销）、属性面板（显示参数、不合法标红不发命令、回车生效）、参数检查和冻结判断。前端用例共 229 个。

### 12.8 补记：文本组件写中文（2026-11-23）

货代单证上的字大多是中文，只能写英文的文本组件用处不大。现在文本组件什么字都能写（只有一行，不能有换行这类控制字符，最多 100 个字）：

- **全是英文字母、数字和常见符号时照旧**用标准字体 Helvetica，不嵌入，文件最小。
- **有别的字时**挑一份覆盖这段文字、许可允许嵌入的系统字体（先找黑体，找不到退到同类、再退到任意一份），塑形、子集化，以 Identity-H 嵌入，带 ToUnicode，复制、搜索得到原文。用的是改字第 3 级（V08）那一套，抽成了 `magpdf-text` 的 `compose::new_text_object`。只嵌用到的字：一段十来个字的文字，整个文件不到 200 KB（整份中文字体有几 MB）。
- 每改一次内容就嵌一份新的子集，旧的随旧对象不再被引用，保存时去掉（V06 第 15 节）：改两次内容再保存，用例核对过只留下最后一份。
- 找不到能显示这些字的字体时报参数不合法（“找不到能显示这些字的字体：……”），标在“内容”上。
- 参数存在标记内容里，中文按 UTF-8 写：PDFium 读标记参数时按 UTF-8 解（先试过写成带 BOM 的 UTF-16BE，读回来只剩 ASCII 的字节）。《文件私有数据格式规范》里组件参数也是 UTF-8。

验证：引擎用例放“提单号：BL-0042”、改两次内容位置不漂、存盘再打开参数和提取出来的文字都对；`magpdf-text` 用例生成文字对象、提取得到原文、文件小于 200 KB。这两条在没有中文字体的机器上跳过（GitHub 的 Windows 机器上就缺中文字体，CI 上跑不到，靠本机）。端到端测试 `components.mjs` 加了一步：拖进来的文本改成“收货人：上海”，引擎重新生成，画面上出现中文（截图 `tests/out/e2e/components-chinese.png`）。

还没做的：字体不能选（以后按《组件参数定义》给文本组件加字体、字重参数）；回退顺序只有“先黑体”一种；多行、对齐、超框处理（《组件参数定义》4.1）。

## 13. 补记：历史记录面板接上引擎的撤销记录（2026-11-23）

11.6 记过“历史记录面板没有接引擎的撤销记录”：引擎打开的文档，面板上一直只有“打开文档”一条。现在接上了。

- **引擎**：撤销栈里每一步记下说法和时刻。说法按命令写：“移动 2 个对象”“变换 1 个对象”（矩阵不只是平移）、“删除 3 个对象”“改 1 个对象的填充色”“置入 Code 128”“改文本参数”“改字”。`Session::history` 列出做过的几步（从早到晚）和撤销了还能重做的几步，`Session::jump` 撤销或重做到只剩前几步生效，几步合成一个变化（一条 `doc.changed`），版本号每步加 1、和逐步撤销一样。
- **协议**：`history.list {docId}` 返回 `{entries: [{index, label, time}], current}`；`history.jump {docId, index}` 返回 `{version}`，`index` 是跳过去之后生效的步数，0 是打开时的样子；原地不动时版本号不变、不推送 `doc.changed`（界面收到它会把文档标成已修改）。和《接口协议》6.8 的出入记在它的 12.3。
- **界面**：每收到一条 `doc.changed` 就取一份撤销栈（上一份还没回来时只记下再取一次，不堆请求），换掉 store 里的历史记录和“现在在哪一步”。面板最新的在上面，现在的位置高亮，撤销了的几步划掉显示；点哪一条就跳到那一条之后的样子，点现在这一条不发。引擎重启之后新引擎的撤销栈是空的，面板只剩“打开文档”。模拟文档照旧只列出来，点不了。

- **菜单**：“编辑”菜单的“撤销”“重做”按历史记录变灰：没有做过的步就不能撤销，没有撤销了的步就不能重做（11.6 记的“一直可点”）。快捷键照旧，没有可撤销的操作时引擎回 3005，界面不提示。

## 14. 补记：属性面板读颜色、改填充色（2026-11-23）

引擎早就能改填充色（`edit.setStyle`，只有 RGB 填充，V06 第 10 节），界面上一直没有地方改。现在属性面板选中一个对象时多一节“颜色”：

- **读**：`obj.get` 加了 `detail: "style"`，返回 `{fill?, stroke?}`（RGB，分量 0–1）。路径按它画的时候填不填充、描不描边给，只描边的方框没有填充色；文字按渲染模式给（不可见、只做剪切的文字两样都没有）；图像这类对象两样都没有，面板不显示这一节。PDFium 给的颜色是换算到 RGB 之后的，原来是 CMYK 也读成 RGB。
- **改**：填充色是一个色块加一个 `#rrggbb` 输入框，大小写都行、`#` 可以不写；回车或离开输入框生效，Esc 恢复，写错了标红、下面写明怎么写，不发命令；回车之后再离开输入框不重复发。界面上不先改，画面由引擎重画。描边色只显示，原型改不了。只能叠加内容的页上原有的对象输入框是灰的。组件不显示这一节（颜色不是组件的参数，改参数重新生成时会变回黑色）。
- **模拟文档**：方块的填充、文字和文字条的颜色能改，落在 store 上。

注意：改过的填充色写成 RGB。原来是 CMYK 或专色的对象改了颜色就变成 RGB，面板上有一句提示。方案 1.2 要求“文件里原有的 CMYK、专色保持原样”，说的是没改的对象；改的时候按原来的色彩空间写，要等 `edit.setStyle` 支持别的色彩空间。

测试（颜色）：引擎（填充的路径读得出填充色、没有描边色；改了读到新的，撤销读回原来的）、引擎进程（样本里只填充、只描边、又填充又描边的都分得出来；只给请求的那一类详情；改了再读是新的）、引擎会话（换成 `#rrggbb`、发出去的分量、写错的和只能叠加内容的页上的不发）、属性面板（显示、写错标红、回车交给引擎不重复发、图像和组件不显示、模拟文档）。端到端 `apps/desktop/e2e/colors.mjs`：点红方块，面板读出 `#cc3333`；写“红色”提示原因、版本号不变；改成 `#1a6fd0`，截图量方块中心的颜色是 (26, 111, 208)；Ctrl+Z 之后颜色和原来逐值相同，面板读回 `#cc3333`（截图 `tests/out/e2e/colors-changed.png`）。

## 15. 补记：调整层级（2026-11-23）

“对象”菜单里的置顶、上移一层、下移一层、置底原来都是灰的。现在接上了：快捷键和 Illustrator、InDesign 一样，Ctrl+] 上移一层、Ctrl+[ 下移一层、Ctrl+Shift+] 置顶、Ctrl+Shift+[ 置底（按着 Shift 时键盘打出来的是 `}`、`{`，组合键里归并成 `]`、`[`）。没选中对象、或者选中的对象在只能叠加内容的页上时，四项都是灰的。

- **规则**：没选中的对象之间先后不变；置顶、置底时选中的几个按原来的先后挨着放；上移、下移一层时越过上（下）面紧挨着的一个对象，挨着的几个选中对象一起动，已经到头的不动。几页上都有选中的对象时各页各排各的，是一步撤销。引擎和模拟文档用同一套规则（`ZOrder::arrange`、`arrangeZOrder`），各有用例。
- **引擎**：把这一页上选中的对象摘下来，按新顺序插回去，生成内容流；撤销按原来的顺序再排一遍。顺序本来就是那样时什么也不做：不记撤销，版本号不变，不推送 `doc.changed`。所在的页要过保真校验，本次新加的组件也一样（见下一条）。历史记录里的说法和菜单一样（“置顶”“上移一层（2 个对象）”）。
- **PDFium 的限制：跨内容流的先后写不下来。** 页面的内容可以分成好几段流（`/Contents` 是数组），PDFium 重新生成时只重写改过的那几段，每个对象写回它原来所在的那一段，段与段的先后不变；对象摘下来再插回去，仍然记着原来那一段，公开接口改不了。结果是：对象分在几段里时，跨段调层级在界面上看着对，存盘再打开就变回去了。引擎的做法是调完之后按内容流重新解析一份这一页，逐个比对象的种类、包围盒和颜色，对不上就把这一步撤回去，报“第 N 页的这几个对象和要越过的对象不在同一段页面内容里，原型还调不了它们的先后”，文档不变。原有内容在同一段里的页（大多数单据）照常能调；新放的组件在 PDFium 追加的另一段里，和原有对象之间调不了，组件之间（每放一个就追加一段）也调不了。分支里已有的补丁“插入时沿用邻居的流”只管没有流的新对象；再让“摘下来的对象忘掉原来那一段”，跨段调层级就能写对，是一个可以提交上游的补丁候选（PDFium 的源码没有动）。
- **界面**：画布控制器收到命令后交给修改入口；界面上不先改，新顺序随对象列表回来，图层面板跟着变。引擎拒绝时弹出提示。

顺带修了改原有文字（V08 第 10 节）的一个问题：引擎把“为什么不能改”放在错误的 `data.detail` 里，`message` 只是笼统的“文字不能改”，界面只显示 `message`，用户看不到原因（假引擎是把原因放在 `message` 里的，所以界面的用例没发现）。现在 4001 和上面跨段拒绝的原因都放在 `message` 里，引擎进程的用例核对了。

测试（层级）：引擎（各种挪法的顺序；置顶、撤销、原地不动不记撤销、跨段拒绝且页面原样、两个对象一起上移、存盘再打开顺序还在）、引擎进程（经管道置顶、原地不动不推送、新放的组件挪到下面被拒绝且原因在 `message` 里、`index` 没给值报错、撤销）、界面（排序规则、快捷键的归并、画布命令交给修改入口、只能叠加内容的页不发、模拟文档改 store、引擎会话发出的参数和原地不动、菜单什么时候是灰的）。端到端 `apps/desktop/e2e/layers.mjs`：点红方块按 Ctrl+Shift+] 到最上面，图层面板最上面一行是它；菜单“对象 > 置底”到最下面；撤销两步顺序回到原样；放一个条码再按 Ctrl+Shift+[，弹出上面那句提示，版本号和顺序都不变（截图 `tests/out/e2e/layers-refused.png`）。

## 16. 补记：图层面板拖动改层级、筛选（2026-11-23）

- **拖动**：图层面板里每一行都能拖（顶层在上）。拖的是选中的那一行时，这一页上选中的几个一起拖；拖的是没选中的，只拖它，并选中它。拖到别的行上时，鼠标在那一行的上半部分就放在它上面、下半部分就放在它下面，有一条线标出来。松手后交给引擎的是 `edit.zOrder` 的 `op: "index"`：没被拖的对象从下往上数，放在第几个之前（第 15 节的规则，跨内容流时一样会被拒绝）。界面上不先改，新顺序随对象列表回来。只能叠加内容的页上、筛选的时候不能拖（筛掉了一些行，“放在哪一行上面”就说不清了）。拖进来的只认图层面板自己拖出来的（自定义的数据类型）。

## 17. 补记：图层的显示、隐藏和锁定（2026-11-23）

图层面板每一行前面多了两个开关：眼睛是显示、隐藏，锁是锁定、解锁。两样都只在本次会话有效（方案 4.3、《接口协议》6.5 `view.setHidden` 说的“不改文档、不改版本号”），不进撤销记录，存盘照样存，悬停在开关上有这句说明。

- **隐藏**：画面上不画它，点选、框选、全选都跳过它，选区里有它就去掉；图层面板里那一行变灰、名字斜体、眼睛变淡，点不了、拖不动（还能当放下的位置）。怎么做到“不画”：没有加 `view.setHidden`，用的是拖动预览（V04）已有的分层渲染。界面请求这一页的整页瓦片时带上 `layer: {mode: "without", objectIds: 隐藏的对象}`，引擎在另开的一份页面句柄上暂时停用这些对象再画，一直开着的那一份不碰，所以存盘、重新生成内容流都不受影响。隐藏的集合变了，这一页的瓦片作废重画；拖动预览的底图也把隐藏的对象一并去掉，不然一拖就露出来。
- **锁定**：照常画，点选、框选、全选都跳过它，选区里有它就去掉；图层面板里那一行变灰、点不了、拖不动。
- **记在哪里**：文档状态里的两份对象编号（`hidden`、`locked`），不在页面快照里：引擎打开的文档每改一次都重新取对象列表，快照会整个换掉。引擎重启之后对象编号是新分配的，旧编号会对到别的对象上，所以恢复时两份都清掉。
- **代价**：有隐藏对象的页，每块瓦片都要另开一份页面句柄、重新解析内容流（不隐藏时画在一直开着的那一份上）。用 V05 的两个 5000 个对象的页量了一次（发布版，1024×640 的测试窗口）：隐藏一个对象之后整屏重画完 151 ms、198 ms；有隐藏对象时放大一档重画完 76–121 ms，没有隐藏时 85–98 ms，差不多。先不缓存另开的那一份。
- 模拟文档的瓦片来源也认 `without`（跳过这些对象）。

测试：store（开关、从选区去掉、清掉）、画布（隐藏之后整页瓦片带 `without`、开关一下重新要、点不中、拖动预览的底图连隐藏的一起去掉、显示回来不再带；锁定的照画、点不中、全选跳过）、图层面板（开关、变灰、点不了拖不动、恢复）、引擎会话（重启之后清掉）。端到端 `layers.mjs` 加了一步：点红方块那一行的眼睛，截图量方块中心变成白底，点它选不中；再点一下颜色逐值回到原样；锁定之后点它选不中，Ctrl+A 全选里没有它；整个过程文档版本号不变（截图 `tests/out/e2e/layers-hidden.png`）。

还没做的：锁定、隐藏都不存进文件（方案里锁定是 `edit.setMeta`，写进《文件私有数据格式规范》的私有数据）；整页的缩略图、导出、打印还没有，以后做的时候要决定隐藏的对象画不画。

## 18. 补记：旋转（2026-11-23）

- **画布**：选中对象后，在选框四角外 6–20 个像素的旋转热区按住拖动，选框跟着转，上方标出转了多少度（顺时针为正，落在 -180°～180°）；按着 Shift 时吸附到 15° 的倍数。松手时绕选区包围盒的中心转过去：交给修改入口的是一条变换（和移动、缩放一样，按页换成各页页面坐标里的矩阵，再换到 PDF 用户空间发 `edit.transform`），一步撤销。转得太少（不到 0.05°）不发。原来松手时什么也不做，状态机里一直留着“P1 再做”的注释。
- **属性面板**：“旋转”原来写死显示 0°。路径的坐标直接写在内容流里，“这个对象现在转了多少度”说不清，所以改成“再转多少度”：输入角度回车，绕对象中心转过去，然后清空；0°、360° 的倍数和写错的不发。只能叠加内容的页上原有的对象、模拟文档（对象只有轴对齐的包围盒，转不了）输入框是灰的。
- 只能叠加内容的页上原有的对象本来就没有旋转热区（第 11.3 节）。旋转之后对象的包围盒是转过之后的外接矩形，再转、缩放都按它来。组件转过之后改参数，会按参数重新生成、转回正的（12.6 说过：原来的缩放、旋转不保留）。

测试：旋转矩阵（中心不动、y 向下时正角度是顺时针、正反抵消）、选择工具（松手交出角度和中心、跨过 180° 时取较小的那一边、Shift 吸附、转得太少不交）、画布（在热区里真的拖 90°，交给修改入口的矩阵绕对象中心）、属性面板（回车交出绕中心的旋转并清空、0°/360°/写错的不发、灰的情况）。端到端 `apps/desktop/e2e/rotate.mjs`：红方块按着 Shift 拖 45°，量画面：原来的角上变白、方块右边外面一点变红，包围盒边长是原来的 √2 倍（60 → 84.9 pt）、中心不动；Ctrl+Z 恢复；再在属性面板里输入 -45 回车，画面同样变成菱形（截图 `tests/out/e2e/rotate-dragging.png`、`rotate-done.png`）。
