# V07 文字块标注格式

文字行 / 段落聚类（方案 5.1、P0 计划 V07）的人工标注与评测格式。评测代码在 `engine/magpdf-text/src/eval.rs`，命令行入口 `magpdf-cli text-blocks`。

## 1. 基本约定

- 一个 PDF 一份标注文件，JSON，UTF-8，扩展名 `.labels.json`，与样本同名放在样本旁边（如 `F-0123.pdf` → `F-0123.labels.json`）。
- 标注的基本单位是 **PDFium 文字页的字符索引**（`FPDFText_GetCharIndex` 的那个索引，从 0 开始），不是坐标。这样评测与渲染分辨率无关，也不依赖包围盒是否贴合。
- 字符索引里包含 PDFium 自己插入的"生成字符"（词间空格、行末 `\r\n`）。它们不属于任何行，**标进去也不扣分**：评测时只看预测结果里出现过的字符；标注里多出来而预测里没有的字符单独计数（`unassigned_chars`），用来发现标注把索引标错的情况。
- 没有标注的字符不参与评测。页眉、页脚、页码、水印可以不标；一页只标部分区域也可以。
- 每行、每段用 **闭区间列表** `[[first, last], …]` 表示；一行通常只有一个区间，被别的文字（上标、夹注）打断时可以是多个。

## 2. 文件结构

```json
{
  "format": "magpdf-text-labels/1",
  "file": "F-0123.pdf",
  "pages": [
    {
      "page": 1,
      "lines": [
        { "chars": [[0, 22]], "bbox": { "left": 213.8, "bottom": 754.1, "right": 381.2, "top": 769.7 } },
        { "chars": [[25, 107]] }
      ],
      "paragraphs": [
        { "chars": [[0, 22]], "note": "标题" },
        { "chars": [[25, 310]] }
      ],
      "note": "页脚未标"
    }
  ]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `format` | 是 | 固定 `magpdf-text-labels/1`；格式变化时递增版本号，评测程序拒绝不认识的版本 |
| `file` | 否 | 样本编号或文件名，只作说明 |
| `pages[].page` | 是 | 页码，从 1 开始；没有出现的页不评测 |
| `pages[].lines[]` | 否 | 行标注；缺省为空数组，表示这页不评测行 |
| `pages[].paragraphs[]` | 否 | 段落（文字块）标注；缺省为空数组 |
| `*.chars` | 是 | 字符索引闭区间列表；区间之间不要重叠；同一类（行或段）的不同标注之间也不要重叠，重叠时以先出现的为准 |
| `*.bbox` | 否 | 页面坐标（点，原点左下）的包围盒，给标注工具显示用，评测不看 |
| `*.note` | 否 | 备注；`--emit-labels --with-text` 产生的预标注会把文字片段写在这里，方便校对，提交到文件库前应删除含敏感信息的备注 |

## 3. 怎样算一行、一段

**行**：同一基线上、属于同一个阅读单元的连续文字。

- 表格同一行里相邻的两个单元格是 **两行**；表单的"标签：内容"如果中间隔开超过一个词距，也算两行。
- 上标、下标、脚注编号并入所在行。
- 两栏排版里左右两栏的同一水平位置是两行。
- 竖排文字（P4 才支持）按列标，一列一行。
- 非 0/90/180/270° 的文字（印章、水印、斜排表头）：一个文字对象标一行。

**段落**：排版意义上的一个文字块——重排时应当一起流动的行。

- 标题自己一段；列表的每一项自己一段（含折行）。
- 表格里每个单元格自己一段（单元格里折成多行也只算一段）。
- 两栏文章的一段跨栏续排时，**按栏拆成两段**（v1 不做跨栏重排）。
- 不可编辑（无 Unicode 映射）的文字照常标，评测时与可编辑的一视同仁。
- 不可见文字（扫描件的 OCR 文字层，`3 Tr`）只在该页专门评测文字层时标。

## 4. 两个指标

都按页计算，再按字符数 / 簇数汇总到整个样本集（`Summary`）。

1. **字符一致率**（主指标；P0 目标：行 ≥ 98%，段 ≥ 90%）
   - 对每个预测簇，找与它重叠字符最多的标注簇；反过来对每个标注簇也找重叠最多的预测簇。
   - 一个字符算对，当且仅当它所在的预测簇与标注簇 **互为**对方的最大重叠簇。
   - 效果：一行被拆成两半时只有较大的一半算对；两行被并成一行时只有较长的一行算对；拆与并都按字符数受罚，一页里一个长段落切错比一个短标题切错扣得多。
2. **完全匹配率**（辅助指标）
   - 标注簇的字符集合与某个预测簇完全相同（只比较标注过的字符）的比例，按簇数计。
   - 对"差一个字"也判错，用来看边界精度；汇报时与字符一致率并列。

`ClusterScore` 字段：`labelled_chars`、`agreeing_chars`、`unassigned_chars`、`labelled_clusters`、`predicted_clusters`（与标注有交集的预测簇数）、`exact_matches`。

## 5. 标注流程（建议）

1. `magpdf-cli text-blocks 样本.pdf --emit-labels 样本.labels.json --with-text` 生成预标注（含文字片段备注和包围盒）。
2. 标注人员对照渲染图（`magpdf-cli render`）修正：合并、拆分、删掉不该标的；索引可从预标注的 `chars` 里抄。
3. 删除含敏感文字的 `note`，与样本一起入库；`manifest.json` 的 `tags` 加 `text-labels`。
4. 复标抽查：每批随机抽 10% 由第二人独立标注，用同一个评测程序把两份标注互相比对（把一份当预测），行字符一致率低于 99%、段低于 95% 的批次返工。
5. 评测：`magpdf-cli text-blocks 样本.pdf --labels 样本.labels.json [--json 结果.json]`。

## 6. 与 OCR 标注（《测试样本收集与脱敏规范》7.1）的关系

OCR 标注面向图像，以四边形坐标和转写文字为单位；本格式面向 PDF 文字层，以字符索引为单位，不含转写。两者不能互换：扫描件的文字层评测仍用 7.1 的格式，本格式只用于原生 PDF 的行 / 段聚类。
