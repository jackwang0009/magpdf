## 1. 目标

为 V02（原版 PDFium 往返测试基线）和 V03（修复内容流生成器）提供一组**每份只针对一个（或一组相关）缺陷**、页面小、对象少、
一眼能看出问题的 PDF；把方案 2.1 的缺陷清单和 2.3 的生成规则逐项变成可执行的样本；同时给测试文件库其他来源目录提供统一的清单工具。

## 2. 方法

### 2.1 生成器

- 位置 `tests/corpus/synthetic/`，Python 3.12 标准库，不依赖第三方包。`python generate.py` 一次重建全部 PDF 与 `manifest.json`；
  `--check` 再运行 `check.py`。
- PDF 语法手写：`pdfgen.py` 负责对象编号、流长度、交叉引用表偏移、交叉引用流（`/W [1 4 2]`，可选 Flate + PNG Up 预测器）、
  对象流（PDF 1.5）、增量更新（`/Prev` 链）、以及故意损坏（xref 偏移错位、不写 xref、`/Length` 写短）。
- 确定性：没有时间戳、没有随机数；`/ID` 取样本名的 MD5；Flate 固定级别 9；`/Info` 不写 `CreationDate`/`ModDate`。
  连续两次生成，58 个 PDF 加 manifest.json 共 68 个文件逐字节相同（§4.3）。
- 二进制素材也由程序生成：最小 ICC v2 矩阵/TRC 配置（524 字节，可把红绿原色对调）、只含直线轮廓的 9 字形 TrueType 字体
  （980 字节，Windows GDI+ 与 PDFium/FreeType 均能加载）、Code 39 条码、Adobe-GB1 CID 换算、ISO 6346 与 GS1 校验位。
- 对象数预期不是事后抄 PDFium 的输出，而是构造时登记：`Content` 构造器每画一个对象就把"按 PDFium 对象模型会产生几个页面对象"
  记下来（一次路径绘制 / 一次 `Tj|TJ|'|"` / 一个 `BI…EI` / 一次 `Do` / 一次 `sh` 各一个；`W n` 与纯状态操作符不计），写进 manifest 的 `expect`。
  首轮 58 份中有 56 份与 PDFium 一致，2 份不一致都是我自己把两个绘制操作符写在一个登记里；修正后全部一致。

### 2.2 校验（`check.py`）

1. 完整性：文件存在，SHA-256 与大小等于 manifest。
2. `magpdf-cli info --json`：能打开；页数、每页宽高（±0.01 pt）、旋转、对象总数及文字/路径/图像/渐变/Form 分类数与 `expect` 一致。
3. 结构：pikepdf（qpdf）打开 + `check_pdf_syntax()`。`check: pass` 的样本不得有任何警告；`check: expect-warn` 的样本必须有警告且仍能打开
   （证明损坏确实做出来了）。
4. `--render DIR` 把每份第 1 页渲染成 PNG（带 `annots` 标签的再渲染一份带批注版本）到 `tests/out/`（已在 .gitignore），供肉眼检查。

### 2.3 清单工具（`tests/corpus/tools/make_manifest.py`）

扫描任意来源目录生成/更新 `manifest.json`：文件名、SHA-256、大小、页数与每页对象统计（调用 `magpdf-cli info --json`，找不到可执行文件时页数为 null 并在 `note` 说明）、
按目录名映射分类字母、`origin` 推断、脱敏字段占位。再次运行时保留人工字段（`license`、`desensitized*`、`reviewed*`、`tags`、`expected`、`issues`、`id`），
删除目录里已不存在的文件，新文件的 `id` 接在最大序号后；输出排序固定，重复运行无差异。已用 PDFium 的 3 个公开文件做了行为测试。
`tests/corpus/public/README.md` 写了公开测试集（PDFium 347 个文件 BSD-3、pdf.js Apache-2.0）的获取方式和不入库规则。

### 4.4 渲染观察（对 V02/V03 有用）

所有 58 份的第 1 页以及多页样本的其余页都渲染并肉眼检查过（`tests/out/synthetic/`，不入库）。与原版 PDFium 渲染相关的发现：

1. **PDFium 确实按嵌入 ICC 转换颜色**（S-0005）：红绿对调的配置下 `(1 0 0)` 渲染为纯绿。这意味着生成器把 ICCBased 颜色写成 `rg`
   时，渲染结果会从绿变红——这类页面在 V02 里一定会被判差异，而且差异像素是整个色块。V03 修颜色空间时 ICCBased 不能简化为 Alternate。
2. **PDFium 的 CMYK→RGB 不是朴素换算**（S-0002）：`0 0 0 1 k` 渲染为深灰（约 RGB 35,31,32），四色黑更黑。注意：如果生成器用同一套换算把 `k`
   改写成 `rg`，像素比对可能**完全看不出差异**，但颜色空间已经丢了。V02 的"无差异"判定应配合方案 2.3 的对象比对或 qpdf 比对内容流操作符，
   不能只信像素比对——S-0001（灰度）同理。
3. **Separation /None 被正确地不画**（S-0003），/All 画成黑。生成器若把专色换算成 RGB，/None 色块会变成可见的黑块——V03 要单独处理 /None。
4. **PDFium 不模拟叠印、忽略 TK**（S-0021、S-0022）：两对/两行渲染完全相同。往返后 OP/op/OPM/TK 丢失在 PDFium 自己的渲染里看不出来，
   必须靠方案 13.2 第 3 项的第二渲染器或内容流比对。
5. **文字状态跨 BT…ET 泄漏**（S-0025 底行、S-0033 原稿）：`Tw`、`Tc` 设置后对后续所有文字块有效，PDFium 的每个文字对象都带着这份状态。
   这正是方案 2.3 开头说的"状态泄漏"，V03 写 `Tc/Tw` 时要注意相邻对象的状态去重（方案 2.3 第 1 条）。
6. **Type3 字体**（S-0031）在 PDFium 里渲染正确：d0 着色字形、d1 形状字形、字形程序里的内联图像蒙版都对。这份是方案 2.1 "整条流损坏"
   的直接验证样本，V02 跑到它时应能看到 Helvetica 文字、绿条、红线一起消失或变形。
7. **可选内容**（S-0053）：屏幕渲染按 /View 用途隐藏了 PrintOnly 图层、显示了 Background 图层，符合规范。打印用途的渲染目前 `magpdf-cli render`
   没有开关（RenderFlags 已有 `PRINTING`），V16 做之前建议给 `render` 加 `--print`。
8. **批注**（S-0054）：`--annots` 时 PDFium 绘制了 Square、Stamp 的外观流，并为没有 /AP 的 Text 批注自动生成了便签图标；Hidden、NoView 正确不显示；
   Popup 未绘制。往返测试应统一用不带批注的渲染，否则自动生成的外观会引入噪声。
9. 非嵌入 STSong-Light（S-0033）在本机被替换为系统宋体，UCS2 编码与 Identity-H CID 编码两行显示一致，证明 Adobe-GB1 CID 换算正确；
   非嵌入中文字体的替代结果与机器字体有关，V02 的基线应在同一台机器上跑。
10. 程序生成的最小 TrueType（S-0030、S-0034）PDFium/FreeType 正常加载并按 /Widths、/W 排布，可作为 V08 子集化嵌入的对照物。

## 5. 结论

- 方案 2.1 列出的六类缺陷（颜色、渐变、ExtGState、文字字距、Type3、层级/多内容流）和 2.3 的四条生成规则（状态去重、剪切共用、文字裁剪整体、标记内容嵌套）
  每条都至少有一份专门样本；9.4/10.6 的不打印图层、13.2 第 4 项的结构校验、V17 第 1 条"不改动直接保存应逐字节相同"（xref 流、对象流、增量更新三种文件形态）也有样本。
- 生成器与校验工具满足工程规范：标准库、确定性、可重复；pikepdf 只作测试工具。
- 对 V02：建议把这 58 份作为往返测试的"烟雾子集"，每次提交都跑；它们页面小、问题明确，比全量统计更快定位是哪一类信息丢了。
  同时根据 §4.4 第 2、4 条，V02 的判定不能只靠像素比对。

## 6. 遗留问题与未覆盖场景

- 未覆盖：加密文件（RC4/AES，含权限密码）、数字签名、PDF/A 元数据与 XMP、AcroForm 表单域与外观状态字典（/AS）、JBIG2/JPX/DCT/CCITT 编码的图像、
  竖排文字（Identity-V / WMode 1）、Type1 嵌入字体（FontFile）、CFF/OpenType（FontFile3）、Type0 多字节非 Identity CMap 嵌入流（/Encoding 为 CMap 流）、
  型 5/7 网格渐变、SMask /Alpha 类型、/BM 数组形式、链接与目录（Outlines）、300 页以上文档与单页上万对象（性能类归 V05）、线性化文件。
  这些大多属于规范 H 类"专项"，建议从公开测试集补，或按需在本生成器里加（加一个样本约 30–60 行）。
- 嵌入的 TrueType 是程序画的直线字形，不是从 Windows 字体裁的子集：标准库没有 TrueType 子集化能力，而把系统字体文件整份嵌入会带来授权问题。
  V08 做出 hb-subset 后可以替换成真正的子集样本。
- `magpdf-cli info` 不输出标记内容 MCID、文字内容、颜色空间名，所以 `expect` 只能比对对象数与页面几何；S-0042 的 MCID、S-0034 的 ToUnicode 复制结果需要
  V02 工具或 pikepdf 脚本另行检查。
- `magpdf-cli render` 没有打印用途开关（见 §4.4 第 7 条）。
- 工作目录里出现了一个不是本任务写的 `tests/corpus/manifest_tool.py`（按 `manifest.csv` 设计），未入库，需要确认归属（见 §7 第 3 条）。

## 7. 对方案与配套文档的修改建议

1. **《测试样本收集与脱敏规范》第 2 节分类**：增加分类 **S 自制针对性样本**（针对引擎缺陷逐项构造、由脚本生成、不计入 A–H 的数量指标），
   或在 H 类下明确"生成器缺陷样本"子类。本轮 manifest 用的是 `S`。
2. **规范第 6 节 manifest 字段**，建议补充（本轮已按此写入 `tests/corpus/synthetic/manifest.json`，`make_manifest.py` 对其他目录也输出同样字段）：

   | 字段 | 说明 |
   |---|---|
   | `size` | 文件字节数，和 sha256 一起做完整性检查 |
   | `title` | 一句话标题 |
   | `group` | 缺陷/场景分组（color、shading、extgstate、text、structure、composite…），报告按它分组统计 |
   | `refs` | 涉及的方案/计划条目列表，如 `方案 2.1 Type3`、`P0 计划 V03 第 5 项` |
   | `expect` | 机器可比对的预期：`pages` 与每页 `width/height/rotation/objects/text/path/image/shading/form`，供 check 工具与 CI 使用 |
   | `check` / `checkNote` | `pass`（结构检查必须干净）或 `expect-warn`（故意损坏，必须报警），区分预期失败 |
   | `pdfVersion` | 文件头版本 |
   | `generator` | 自制样本的生成脚本路径，表明可重新生成 |
   | `note` | 自由备注（如"由 .in 模板生成"、"magpdf-cli 打不开"） |

   另外两处需要定稿：(a) 规范第 6 节写的是全库一份 `tests/corpus/manifest.csv`，而 `tests/corpus/README.md` 写的是每个目录一份 `manifest.json`，
   本轮按 README 做（JSON 便于放 `expect` 这类嵌套结构）。建议规范改为"每目录一份 `manifest.json`，字段同第 6 节，CI 汇总"；
   (b) 规范 `expected` 字段的语义建议明确为"要观察的现象 / 已知问题"，与机器比对的 `expect` 区分。
3. **《P0 技术验证计划》V14**：补一句"自制样本（`tests/corpus/synthetic/`）作为往返测试的烟雾子集，每次 PR 必跑"；V02 的判定方法补"像素比对之外，
   用 qpdf 或 pikepdf 比对往返前后内容流的颜色/状态操作符"，理由见 §4.4 第 2、4 条。
4. **《方案》2.1 颜色空间一条**：补充"ICCBased 颜色 PDFium 渲染时经 lcms 按配置转换，写回时不能退化为 Alternate 或 DeviceRGB"（§4.4 第 1 条）；
   专色一条补充"/None 着色剂必须保持不画"。
5. **《方案》13.2 第 1 项 / 2.3 保真校验**：明确像素比对对"颜色空间被换算成等价 RGB"不敏感，对象比对要比较颜色空间类型而不只是 RGB 值。
6. **《工程规范》第 5 节**：测试工具依赖登记——pikepdf 10.17.0（MPL-2.0；二进制轮子内含 qpdf Apache-2.0、libjpeg-turbo、OpenSSL、zlib）、lxml（BSD-3-Clause，pikepdf 的依赖）；
   只在开发机/CI 用 pip 安装，不进产品。建议在 `tests/` 下放 `requirements-test.txt`。
7. **`magpdf-cli`**：`render` 增加 `--print`（`FPDF_PRINTING`）开关，V16 直接用 S-0053 验证；`info --json` 增加每个对象的 MCID 与颜色空间类型，让 `expect` 能覆盖 S-0042、颜色类样本。
