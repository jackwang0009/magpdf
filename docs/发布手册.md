## 1. 范围

安装包、代码签名、自动更新、离线安装、回滚、崩溃转储和诊断包的处理，以及每次发布的流程和检查表。

## 2. 发布产物

| 产物 | 说明 |
|---|---|
| 在线安装包 `MagPDF-<版本>-setup.exe` | 基础安装（未压缩约 110–155 MB，方案 12.1）；Windows 10 上没有 WebView2 时，安装程序检测并安装 |
| 完整版安装包 `MagPDF-<版本>-full-setup.exe` | 另含高精度 OCR 模型和 WebView2 离线安装程序，用于断网环境（方案 1.1、13.4） |
| 企业部署包 `MagPDF-<版本>.msi` | 供公司 IT 用组策略批量分发 |
| 更新包 | 自动更新用的安装包和签名文件 |
| 可选组件包 | 高精度 OCR 模型（约 165 MB）；P4 起有 LaMa 修复模型 |
| 调试符号 | PDB 文件，内部归档，不发布 |
| 第三方许可声明 | 见《开源许可与合规清单》 |

**安装方式**：
- 安装程序由 Tauri 打包（NSIS）。默认按当前用户安装到 `%LOCALAPPDATA%\Programs\MagPDF`，不需要管理员权限；支持 `/S` 静默安装。
- MSI 安装到所有用户，需要管理员权限。
- 安装时询问是否把 MagPDF 设为 PDF 的默认打开程序，默认不勾选；只在"打开方式"里注册。关联 `.maglic` 授权文件，双击即导入。
- 卸载默认保留用户数据（`%APPDATA%\MagPDF` 里的模板、组件、设置和授权）；勾选"同时删除我的模板和设置"才删除。

## 3. 版本节奏

- 版本号规则见《工程规范》第 8 节；发布分支 `release/x.y`，修订版 `x.y.z` 只含缺陷修复。
- Beta 期间每周一个 `1.0.0-beta.N`（《测试计划》第 8 节）。
- v1.0 之后每 4–6 周一个修订版；v1.1 约在 v1.0 之后 12 周（方案 14.4）。

## 4. 代码签名

- **签什么**：安装程序、更新包、MSI，以及安装后的所有可执行文件和我们自己构建的 DLL（主程序、引擎进程、PDFium、ONNX Runtime、OpenCV 等）。
- **证书**：组织验证（OV）或扩展验证（EV）的代码签名证书。按 CA/B 论坛的要求，私钥必须存放在硬件里（USB 密钥或云端硬件安全模块），所以签名在插着硬件密钥的专用签名机上进行，或者使用 CA 提供的云签名服务。
- **提前申请**：实名审核和硬件密钥寄送要花一段时间，P2 开始时就申请。
- **时间戳**：签名时加 RFC 3161 时间戳，证书过期后已签的文件仍然有效。
- **SmartScreen**：新证书、新程序需要积累下载信誉，最初一段时间用户可能看到"Windows 已保护你的电脑"。Beta 版本就用正式证书签名，提前积累信誉；《用户手册》里说明遇到时怎么处理。
- **续期**：证书到期前 60 天续期。

## 5. 自动更新

- **机制**：用 Tauri 的更新插件。更新清单（JSON）放在静态下载地址上，写明版本号、发布说明、发布日期、下载地址和签名（方案 13.4）。
- **签名**：更新包用单独的更新签名密钥签名，公钥内置在软件里，安装前校验，校验不过不安装。私钥只在签名机上，或经受保护的密钥管理服务注入发布流水线，不以明文形式存放在 CI 里。
- **检查**：启动时检查一次，之后每 24 小时一次。发现新版本时提示，用户确认后在后台下载，退出程序时安装。偏好设置里可以关闭自动检查。
- **分批推送**：清单里写推送比例；客户端用本机安装 ID 算出一个固定的随机数，决定自己是否在本批之内。新版本先推 10%，3 天内没有严重问题再推全部用户。软件不收集使用数据，所以分批期间靠客服反馈和用户发来的诊断包判断有没有问题。
- **离线升级**：下载完整版安装包覆盖安装即可（方案 13.4）。
- **安装失败**：保留旧版本，可以重新下载。

## 6. 回滚

更新只能升级，不能降级。发现严重问题时：
1. 立即把更新清单的推送比例改为 0，停止推送。
2. 修复后发布一个更高的修订版号，例如 1.0.3 有问题就发 1.0.4。
3. 需要马上恢复的用户：从下载页取上一版本的完整安装包，卸载后安装。卸载默认保留用户数据，模板和设置不会丢。

所有发布过的安装包永久保留（《工程规范》第 7 节）。

## 7. 崩溃转储与诊断包

- 崩溃转储写在本机的 `%LOCALAPPDATA%\MagPDF\logs\`，不自动上传（方案 13.4）。
- 用户通过帮助 > 导出诊断包打包：日志、崩溃转储、系统信息、软件版本、已安装的组件。默认不含文档内容；用户可以勾选附上出问题的文档。
- 技术支持收到后，用归档的 PDB 符号分析崩溃转储，记录缺陷。附带文档的诊断包按《测试样本收集与脱敏规范》当作真实样本处理：要入库的先脱敏，其余用完即删。
- 诊断包在问题关闭后 30 天内删除。

## 8. 发布流程

1. **冻结**：发布分支只接收缺陷修复；更新版本号和发布说明。
2. **构建**：发布流水线从版本标签构建全部产物，同时生成依赖清单和第三方许可声明。
3. **签名**：在签名机或云签名服务上签所有可执行文件和安装包，并生成更新包签名。
4. **验证**：在干净的 Windows 10、Windows 11 虚拟机上安装、覆盖升级、卸载；用 `signtool verify /pa /v` 校验签名；冒烟测试：打开、编辑、保存、打印到 PDF、OCR、条码生成和回读。
5. **发布**：上传安装包和更新包；更新清单先按 10% 推送。
6. **观察**：3 天内关注客服反馈和诊断包，没有 S1、S2 级问题后推送比例改为 100%。
7. **归档**：产物、PDB、发布说明、检查表一起归档。

## 9. 发布检查表

| 项 | 检查内容 |
|---|---|
| 质量 | 发布正式版时，《测试计划》第 9 节的发布标准全部满足 |
| 版本信息 | 版本号和发布日期正确写入程序（授权校验用到发布日期，《授权与定价方案》5.2） |
| 签名 | 所有可执行文件和安装包已签名、带时间戳，校验通过 |
| 更新 | 更新包签名校验通过；更新清单格式校验通过；推送比例设为 10% |
| 安装 | 在线安装包、完整版安装包、MSI 在干净的 Windows 10、11 上安装成功；断网环境能用完整版安装 |
| 升级 | 覆盖升级后，模板库、组件库、设置和授权都还在 |
| 卸载 | 默认保留用户数据，勾选后才删除 |
| 许可 | 第三方许可声明与构建产物一致（《开源许可与合规清单》第 4 节） |
| 文档 | 《用户手册》和发布说明已更新 |
| 符号 | PDB 已归档 |
| 回滚 | 上一版本的完整安装包可以下载 |

## 10. 发布说明模板

```
MagPDF <版本号>（<发布日期>）

新功能
- …

改进
- …

修复
- …

已知问题
- 问题描述。规避办法：…

升级说明
- 自动更新或下载完整版安装包覆盖安装；模板、设置和授权会保留。
```

发布说明用用户能看懂的话写，不写内部术语和缺陷编号。

## 11. 下载与更新服务

- 安装包、可选组件和更新清单放在对象存储加 CDN 上，全程 HTTPS；优先选国内访问快的云服务，海外用户另配节点。
- 官网下载页和更新清单用同一个存储。
- 访问日志保留 30 天后删除，与隐私声明一致（《开源许可与合规清单》第 5 节）。
